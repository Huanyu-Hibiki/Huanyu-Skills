# xianyu-skill · 闲鱼虚拟商品运营合集（路由器）

围绕"把一个 AI Skill / 虚拟资料包在闲鱼上卖好"这一件事，三个功能各由一个子 skill 负责，全部位于本目录下：

| 子 skill | 职责 |
|---|---|
| [01-detail-images](01-detail-images/SKILL.md) | 生成商品详情图：封面（1:1）+ 竖版轮播详情图（3:4），HTML 出图，3 版风格先选后做 |
| [02-listing-copy](02-listing-copy/SKILL.md) | 生成商品描述：3 版标题 + 爆款结构正文 + 闲鱼禁词合规自检 |
| [03-hot-analysis](03-hot-analysis/SKILL.md) | 爆款拆解：同赛道竞品的封面七维拆解 + 文案六维拆解 + 数据解读 + 行动建议 |

本文件是**总协议 + 路由器**（参照 skill-master 模式）：收到请求只做路由分发，不重复子 skill 的工作流细节。

## 总协议（三原则）

1. **商品档案是唯一真相源**：每个商品建一个商品目录，商品信息统一写在 `<商品目录>/商品信息.md`；功能 1/2/3 都从这里读、往这里写，不凭聊天记忆复述商品卖点
2. **合规先于转化**：任何图片文字、文案先过闲鱼禁词红线（见 02 的 compliance-checklist），再谈吸引力；涉及禁售类目直接拒绝
3. **先给看得见的选项，再执行**：详情图先出 3 版真实预览、文案先给 3 版标题——用户在视觉和文字上做选择，AI 不替用户定稿

## 路由表（触发词 → 子 skill）

| 用户说 | 路由到 | 前置条件 | 产出 |
|---|---|---|---|
| "生成详情图" / "做商品图" / "封面图" / "详情页图" / "闲鱼配图" | 01-detail-images | 商品档案（没有则现场收集） | 封面 PNG + 轮播详情图 PNG（可直接上传） |
| "写商品描述" / "闲鱼文案" / "上架文案" / "商品标题" | 02-listing-copy | 商品档案（没有则现场收集） | 3 版标题 + 正文 + 合规自检结果 |
| "分析爆款" / "拆解这个竞品" / "为什么卖得好" / "同赛道分析" | 03-hot-analysis | 竞品素材（图片 + 商品信息，格式同 template/店铺参考） | 拆解报告 + 5 条可迁移行动建议 |

**组合模式（整包请求"帮我把上架都弄好 / 全套准备"类必走，固定顺序串行）**：

1. **建商品档案**：`<商品工作根目录>/<商品名>/商品信息.md`（根目录 = 当前工作目录下 `闲鱼上架/`，**不是商品源文件所在目录**；用户显式指定则用指定值）；信息不全按 02 的最小清单一次问全
2. **03 拆爆款（可选）**：用户有竞品素材才跑；没有则主动索要一次，拿不到就跳过，不阻塞
3. **02 写文案**：3 版标题 🛑 等用户选定、正文定稿后才进下一步
4. **01 出详情图**：**必须等 02 定稿后开工**（图上钩子词与正文一致），3 版风格 🛑 等用户选定

串行依赖不可跳：01 的图上钩子词依赖 02 的定稿文案，倒序执行 = 图文不一致返工。三个子 skill 共用同一份商品档案，拆解结论沉淀进档案供 01/02 调用。

## 防抢触发负例

以下请求**含相似关键词但不是本合集的事**，不路由：

| 用户说 | 不路由，因为 |
|---|---|
| "生成 PPT / 做幻灯片" | 对象是 PPT 而非闲鱼商品图，走 frontend-slides / PPT 类 skill |
| "分析这个店铺的数据报表" | 对象是经营数据表格，非封面/文案拆解 |
| "写小红书 / 抖音文案" | 对象是其他平台，规范和模板不通用 |
| "闲鱼纠纷怎么处理" | 对象是交易争议，不是内容生产，参照闲鱼官方规范即可 |

判别标准一句话：**产出物是否用于闲鱼商品页（图片/标题/描述）**。是 → 路由；不是 → 不接。

## 商品目录约定（单商品单目录）

**🔴 产出与商品源分离（不可违反）**：所有产出（商品档案 / 图片 / HTML / 文案 / 拆解报告）一律写入**用户当前打开的项目路径**（Agent 工作目录，cwd）——**绝不写进商品源目录**。商品源目录（skill 本体、资料包所在的仓库/文件夹）只读，仅作为取材来源（读它的 SKILL.md / README / 截图提炼卖点）。

- 商品工作根目录 = 当前工作目录下 `闲鱼上架/`（用户显式指定则用指定值）
- 例：项目打开在 `C:\work\test`，商品源在 `D:\skills\oracle-bone` → 产出落 `C:\work\test\闲鱼上架\oracle-bone\`；`D:\skills\oracle-bone` 只读不写
- 自检：任何写文件动作前，看目标路径是否在商品源目录下——是 = 停，改写到当前工作目录

每个商品一个子目录，三个子 skill 共用的产出落盘结构：

```text
<商品工作根目录>/<商品名>/
├── 商品信息.md            # 商品档案：卖点/价格/交付方式/数据背书/爆款拆解结论（真相源）
├── images/                # 导出 PNG（直接上传闲鱼，01-封面.png 起编号）
├── detail-html/           # 详情图 HTML 源文件（可改可重出）
└── 文案/
    ├── 标题-3版.md
    └── 商品描述.md
```

## 失败分支（fallback）

| 触发条件 | 一线处理 | 仍失败兜底 |
|---|---|---|
| 商品信息不完整（整包请求只给商品名，或缺价格/交付方式等关键字段） | 按组合模式 Step 1 建档案，按 02 的最小问题清单现场收集（商品是什么/价格/交付方式） | 用户拒绝回答 → 基于合理假设起草并标注 assumption，不阻塞 |
| 组合模式中用户拿不出竞品素材（03 前置缺失） | 03 跳过不阻塞，直接进 02（组合模式 Step 2 的既定分支） | 用户后续提供素材时补跑 03，结论回写商品档案 |
| 发现产出写进了商品源目录（skill 本体/资料包所在处） | 立即停止写入，把已产出文件迁移到当前工作目录的商品目录，向用户说明 | 商品源目录已残留多余文件 → 列出清单请用户确认后再清理 |
| 竞品素材只有图片没有商品信息.md | 按 03 的口径直接从图片拆解封面，数据列标"未知" | 拆解结论注明"缺文案对照，可信度降级" |
| 截图工具不可用（无 npx / playwright 装不上） | 见 01 的 production-spec 重试顺序 | 交付 HTML 源文件 + 手动截图指引（浏览器开 1080×1440 窗口截图） |
| 商品涉嫌禁售类目（外挂/代刷/翻墙/接码等） | 🔴 直接拒绝并说明触发的红线条款 | 无兜底——合规问题不折中 |
| 用户要求图片或文案引导加微信/QQ | 🔴 拒绝，解释站外引流属违规且会被限流降权 | 无兜底 |

## 扩展规则

- 新增子功能：在根目录新增编号子目录 + 本文件路由表登记一行
- 新增封面风格：先进 01 的 style-library.md，标注灵感来源店铺，再投入使用
- 新增竞品样本：按 template/店铺参考 的文件夹格式（图片 + 商品信息.md）归档，并把数据补进 benchmark-shops.md
