# 02 · 商品描述生成（xy-listing-copy）

闲鱼文案的目标函数：**搜索能命中（标题关键词）+ 划到能停留（首句钩子）+ 看完敢下单（信任与交付清晰）+ 不触发平台审核（合规）**。结构和素材来自 `template/店铺参考/` 的爆款实拍（详见 [references/copy-playbook.md](references/copy-playbook.md)）。

## 🔴 不可妥协原则

1. **合规自检是发布前置门**：任何文案产出后必须跑 [references/compliance-checklist.md](references/compliance-checklist.md) 全表，任何一条命中 → 改写后重检，不自检就交付 = 违规交付
2. **不编造**：销量数字、用户评价、背书信息必须来自商品档案；没有就不写
3. **虚拟商品必须写清三件事**：交付方式（怎么发）、售后政策（退不退）、使用门槛（需要什么环境/基础）——同赛道爆款无一例外都有这句，缺了就是售后纠纷源
4. **真实完整披露**：按闲鱼规范"描述不符"条款（用户收到的与描述不一致 = 违规），能力边界、适用范围、不适用场景要写明，不夸大

## 工作流

### Step 1 · 读商品档案（或现场收集）

读 `<商品目录>/商品信息.md`。若刚跑过 03-hot-analysis，先读档案里的"爆款拆解结论"，把其中**钩子词、标题关键词、文案结构**迁移过来。字段缺失则一次问全，按两级处理：

| 级别 | 字段 | 缺失时 |
|---|---|---|
| 必须问 | 商品是什么 / 价格 / 交付方式 | 🛑 停下问，问不到不写 |
| 可推断 | 卖点（从商品性质推）/ 使用门槛（临时通用表述 + 标注"待商家补充"）/ 目标买家 | 先按推断起草，交付物中显著标注推断项 |

### Step 2 · 出 3 版标题（🛑 等用户选择）

三种关键词策略各出一版，每版 30 字内（闲鱼标题超长会被截断）：

| 版本 | 策略 | 公式 | 例（参照真实爆款改写） |
|---|---|---|---|
| A 搜索版 | 堆精准搜索词，命中"搜 skill / AI 工具"的人 | `核心词 + 品类词 + 平台词` | 「剪映自动化 skill｜AI 写文案配音字幕一条龙」 |
| B 痛点版 | 场景痛点开头，命中"刷到但没搜"的人 | `痛点场景 + 解法 + 结果` | 「别再手动剪视频了，AI 一条命令全搞定」 |
| C 人群版 | 圈定身份，命中"对号入座"的人 | `人群 + 核心利益 + 门槛消除` | 「给不会编程的你：装上就能用的 AI 技能包」 |

展示 3 版 + 每版一句话"命中谁"，**等用户选定**（用户可混搭改词）。

**用户未选择分支（批量/非交互模式）**：三版全量交付，每版标注适用场景与首推版，并显著注明"标题未经用户选定，发布前需人工确认"；不得只交付一版冒充已选定。

### Step 3 · 按爆款六段式写正文

结构模板（每段的作用与写法详见 copy-playbook.md）：

```markdown
【首句钩子】一句话说清"这是什么 + 给谁用"（≤30字，搜得到也看得懂）

【这是什么】1-2 句：商品本质 + 适配平台/环境（如"配置到 AI 上的技能包，装好直接对话使用"）

【能解决什么】3-6 条 ✅ 列表：每条 = 能力 + 用户收益（写"自动字幕毫秒级对齐"，不写"支持字幕功能"）

【内含什么】数字化清单：N 个文件 / N 套模板 / N 页文档——数字是信任的最小单位

【怎么交付】拍下后怎么发（网盘/自动发货/秒发）+ 使用门槛（需要什么环境，照店铺4"需基础 Python 环境"的诚实写法）

【售后说明】虚拟商品性质声明 + 退款政策 + 常见问题 1-3 条（Q&A 式，参照店铺3）
```

长度基准：正文主体 150-400 字（**含标点，不含标题与 Q&A 段**；Q&A 是独立加段，参照店铺3）；超过 500 字完读率骤降，先砍形容词再砍重复卖点。

### Step 4 · 合规自检（🔴 强制，输出自检结果）

跑 compliance-checklist.md 全表，**把结果附在交付物里**：

```markdown
## 合规自检
- [x] 无禁售类目关联（AI skill 属可发布虚拟资料）
- [x] 无绝对化用语 / 收益承诺
- [x] 无站外引流信息
- [x] 交付方式、售后政策已写明
- [x] 无虚构数据背书
- 结论：✅ 可发布
```

任何一项不过 → 当场改写 → 重新自检 → 再交付。

### Step 5 · 收尾

落盘 `<商品目录>/文案/标题-3版.md` 与 `文案/商品描述.md`（正文含自检结果）。在 `商品信息.md` 追加发布记录（日期 + 选定标题版本）。

交付时一并给出**发布建议**（定价参照 [../shared-references/benchmark-shops.md](../shared-references/benchmark-shops.md) 价格带：引流款 2.99-6.99 配短文案 / 主力款 9.9-19.9 配完整六段式 / 利润款 29+ 配服务与教学承诺；另给 1-2 条可执行发布项，如首图与标题的 A/B 顺序）。

推荐下一步：跑 01-detail-images 出详情图，图上钩子词与本正文保持一致。

## 人 × AI 分工

- **人**：提供商品信息与真实背书、选标题版本、终审定稿
- **AI**：出 3 版标题、写正文、跑合规自检、给发布建议（价格带参照 benchmark-shops.md 同类商品 2.99-29+ 元区间）

## 反例黑名单（不要做）

| # | 反例 | 为什么 |
|---|---|---|
| 1 | 标题堆砌表情符号和营销词（"🔥🔥全网最全💥秒杀"） | OCR 命中"最全"等词直接限流；表情堆砌降搜索权重 |
| 2 | 正文写成产品说明书（功能罗列无收益） | 买家买的是"能得到什么"，不是功能列表 |
| 3 | 写"加微信详细聊 / 看主页 Q" | 站外引流，违规且限流 |
| 4 | 写"稳赚""必涨""包过""看完就能接单月入过万" | 虚假承诺，虚拟服务纠纷高发词，平台重点打击 |
| 5 | 隐瞒使用门槛（需要付费 API/会员环境不写） | 描述不符 → 到手差评与退款纠纷 |
| 6 | 一段到底不分段 | 手机端阅读体验极差，完读率归零 |

## 失败分支（fallback）

| 触发条件 | 一线处理 | 仍失败兜底 |
|---|---|---|
| 商品信息严重不足（说不出是什么） | 按 Step 1 清单现场问 | 拒绝凭空编写——写了就是编造 |
| 商品涉及 borderline 类目（如选股分析、占卜建议类 skill） | 按 compliance-checklist 的类目细则处理：去投资建议化措辞（改"辅助研究/不构成建议"），仍踩线则拒写 | 无兜底 |
| 用户坚持要加站外联系方式 | 🔴 拒绝并解释后果（限流/封号），提供替代：闲鱼私聊自动回复 | 无兜底 |
| 用户嫌合规改写"没内味了" | 给出同赛道的合规爆款例句作对照，说明钩子靠结构与场景不靠违规词 | 用户坚持 → 停止服务并留档说明 |
