# PPT Design Skill 实施计划

## 总览

本计划创建一个名为 `ppt-design` 的可复用 skill：以主题采访或原始材料为入口，先产出经用户确认的 `PPTDESIGN.md`，再通过原生 PPTX 对象创建可编辑演示稿。实现采用渐进式资源加载，重用参考项目的设计和验证经验，但不复制图片型或 HTML 型成品路线。

## 前置准备

- [x] 已批准设计文档：`docs/designs/2026-09-18-ppt-design-skill-design.md`。
- [x] 搜索当前仓库和运行时中可用的 PPTX 生成、渲染与验证能力。
- [x] 为行为测试确定可重复的最小示例和临时输出目录。
- [x] 前置设计与运行时能力已完成确认；最小示例由 pytest 覆盖。

## 任务列表

### 任务 1: 用户可通过一次只问一题的采访形成可确认设计
- **状态**: 已完成（采访相关 pytest 6 passed；quick_validate 通过；规格、质量与安全复审无阻塞问题）
- **交付**: 用户只给出一个 PPT 主题时，skill 能按回答状态逐轮提出唯一的高价值问题，最终生成包含叙事、视觉 tokens、逐页大纲与待确认项的 `PPTDESIGN.md`。
- **验收标准**:
  - [x] 每个采访回合恰好询问一个问题，且没有回答不会进入下一回合。
  - [x] 设计文档有来源、设计 tokens 和逐页规格的明确结构。
  - [x] 设计文档展示后停止，不生成 PPTX 直到用户明确确认。
- **阻塞边**: 无。
- **安全**: 是（外部资料、用户提供材料与版权/来源边界）。

### 任务 2: 用户可从原始材料形成可确认设计
- **状态**: 已完成（材料相关 pytest 5 passed；mypy 与 quick_validate 通过；规格、质量与安全复审无阻塞问题）
- **交付**: 用户提供材料时，skill 能优先提取材料事实、只补问一个改变设计的关键问题，并创建同一契约的 `PPTDESIGN.md`。
- **验收标准**:
  - [x] 材料清单、主来源和空白项可见。
  - [x] 外部补充事实附带来源、日期和用途；不确定内容被标记。
  - [x] 该模式与采访模式共用确认门和设计文档格式。
- **阻塞边**: 任务 1。
- **安全**: 是（外部资料、用户提供材料与版权/来源边界）。

### 任务 3: 用户确认后可获得对象级可编辑 PPTX
- **状态**: 已完成（原生文字、形状、表格、图表；16 项测试与静态检查通过）
- **交付**: 用户确认 `PPTDESIGN.md` 后，skill 将逐页规格渲染为原生可编辑 PPTX 并生成可审阅预览。
- **验收标准**:
  - [x] 输出含可编辑文字、形状、表格和图表，而不是整页位图。
  - [x] 输出文件可被标准 PowerPoint 读取，且预览可用于视觉检查。
  - [x] 只在确认后执行，修改请求能回到设计文档再生成。
- **阻塞边**: 任务 1、任务 2。
- **安全**: 否。

### 任务 4: 维护者可验证完整流程与关键不变量
- **状态**: 已完成（16 项 pytest、mypy、ruff、quick_validate 全部通过）
- **交付**: 维护者可运行静态和工件验证，确认两种入口、确认门、来源记录和 PPTX 可编辑性没有回归。
- **验收标准**:
  - [x] skill 元数据与资源引用通过校验。
  - [x] 两种代表性输入均通过行为检查。
  - [x] 最小 PPTX 示例通过生成和预览检查。
- **阻塞边**: 任务 3。
- **安全**: 是（验证来源记录和用户材料边界）。

## 并行机会（frontier）

任务 1 是基础契约；任务 2 在其契约稳定后实施。任务 3 依赖两种输入均能生成一致的设计文档。任务 4 是最终集成验证。

## 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|
| PPTX 生成能力在本机不可用 | 中 | 高 | 搜索现有运行时能力；选择稳定对象级生成库并以最小 deck 验证 |
| 复杂视觉无法完全映射为对象 | 中 | 中 | 保留照片/插图为资产，所有结构与内容元素使用原生对象 |
| 材料事实与外部资料冲突 | 中 | 高 | 材料优先，冲突显式标记并在确认前交给用户裁决 |
