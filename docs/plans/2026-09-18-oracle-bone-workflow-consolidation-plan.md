# oracle-bone 工作流收敛实施计划

## 总览

本计划按已批准设计将 oracle-bone 收敛为 26 个 skill：统一 study 与 cover 的用户入口，移除已由 video-production-workflow 覆盖的制作层，并让根 skill 从静态触发词表升级为最小任务路由器。旧入口只保留兼容别名，不保留重复实现；本轮不新增 dbskill 的资产工程或理论研究子系统。

## 搜索结果

- 现有方案：oracle-bone 已有根路由表、context 摘要器、行为用例与预算测试；video-production-workflow 已有独立的制作、动效逆向、B-roll、剪辑与 QA 路由。
- 选择：复用这些既有契约与测试 seam，不新建制作中间层，也不复制 VPW 的动效分析。
- 约束：主 `SKILL.md` 当前 30,971 bytes，距 31,000-byte 预算仅 29 bytes；新增入口行为必须通过删减旧表述或下沉按需协议完成。

## 前置准备

- [ ] 设计文档已批准，压力测试决策已回写。
- [ ] 运行既有 unittest 基线并确认通过。
- [ ] 确认 TDD seam：文档/静态一致性、路由行为、工件契约。

## 任务列表

### 任务 1: 用户可从一个 study 入口完成对标学习
- **交付**: 用户以账号、作品、机制或工作流为对标对象时，可以在 benchmark、practice 与 dual 模式中得到正确的最小流程、共享素材约定和可验证结论；旧学习入口显示迁移提示后进入该实现。
- **验收标准**:
  - [ ] benchmark 保留样本、数据、印象和“不可直接改 rubric”的约束。
  - [ ] practice 保留用户复述、质疑、迁移、轨道落点和三重验证门。
  - [ ] dual 推荐但不替用户决定深拆样本，且不把统计关联当作可复制机制。
  - [ ] 视频包装/动效逆向请求明确路由 VPW。
  - [ ] 旧学习工件可读；迁移须先确认。
- **阻塞边**: 无。
- **安全**: 否。

### 任务 2: 用户可从一个 cover 入口生成或分析封面
- **交付**: 用户对定稿请求封面时可生成提示词，对参考图请求分析时可沉淀结构配方；旧分析入口兼容路由到统一实现。
- **验收标准**:
  - [ ] 两个模式的输入分流、确认点和工件契约明确。
  - [ ] 分析仅提炼结构与视觉逻辑，不复制受保护身份、品牌或文字。
  - [ ] 既有配方继续是生成模式的可选框架来源。
- **阻塞边**: 无。
- **安全**: 否。

### 任务 3: 用户的根请求按最小范围直接进入正确工作流
- **交付**: 用户调用根 oracle-bone 并给出明确自然语言目标时会直接进入一个合适的 leaf skill；不明确时只获得一个改变路由的澄清问题；旧制作/视觉请求转交 VPW。
- **验收标准**:
  - [ ] 路由不自动展开成长链，也不绕过 predict、shoot、publish、retro 的不变量。
  - [ ] 输出区分事实、用户经验、AI 推断和待验证假设。
  - [ ] 只交付当前请求范围，并禁止推测对标对象的私人动机或能力。
  - [ ] 兼容名称不会回到删除的旧实现。
- **阻塞边**: 任务 1、任务 2。
- **安全**: 否。

### 任务 4: 用户不会再从 oracle-bone 进入视频制作层
- **交付**: 用户在 oracle-bone 完成终稿后被清楚交给 VPW 制作；已发布后的 URL 与数据再回到 oracle 的校准循环，skill 包中不再声明、路由或维护剪辑计划与成片验收。
- **验收标准**:
  - [ ] 制作 skill、目录 schema、模板、context 读取项和运行时路由已移除或改为 VPW 边界。
  - [ ] 不删除用户内容项目中既有历史 `edits/` 工件。
  - [ ] 当前运行时引用 oracle-bone；cheat-on-content 仅在历史来源语境保留。
  - [ ] 安装、卸载、文档、行为用例、测试提示和计数保持一致。
- **阻塞边**: 任务 1、任务 2、任务 3。
- **安全**: 否。

### 任务 5: 维护者可验证收敛后的 26-skill 契约
- **交付**: 维护者运行既有校验时能验证预算、摘要器、路由行为和删除项没有残留；设计与维护文档记录迁移边界。
- **验收标准**:
  - [ ] 新旧触发词、模式边界与 VPW 委派拥有可观察的行为用例。
  - [ ] Python 单元测试、语法检查及相关静态断链检查通过。
  - [ ] 主 skill、子 skill、协议均不突破棘轮预算。
- **阻塞边**: 任务 4。
- **安全**: 否。

## 并行机会（frontier）

任务 1 与任务 2 互不阻塞。任务 3 依赖两者的术语和兼容策略；任务 4 依赖统一路由边界；任务 5 负责最终集成验证。

## 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|
| 主入口超出上下文预算 | 高 | 高 | 先删旧路由文本，再下沉模式协议；每个切片运行预算测试 |
| 旧入口或安装器仍指向删除目录 | 中 | 高 | 用全仓搜索与行为用例验证兼容名称和目录清单 |
| oracle 与 VPW 重复分析视觉制作 | 中 | 中 | `--visual` 统一路由 VPW，study 只保留文本与机制层 |
| 旧用户 study 数据被误移动 | 低 | 高 | 仅可读兼容；迁移必须展示影响并等待确认 |
