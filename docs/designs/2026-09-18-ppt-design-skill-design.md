# PPT Design Skill 设计

## 目标

在 `PPT-design` 中创建一个可复用的 `ppt-design` skill。它将用户需求或原始材料转为经用户确认的 `PPTDESIGN.md`，再生成真正可编辑的 PowerPoint 文件，而非把整页图像嵌入 PPTX。

## 已确认边界

- 入口有两种互斥模式：主题采访与原始材料。
- 主题采访先确定主题，再以一问一答方式收集需求；每轮只能问一个问题，必须收到回答后才可继续。
- 原始材料模式接受用户提供的文档、提纲、表格、链接或现有 PPT，并以其为主要事实来源。
- 两种模式均必须生成并展示 `PPTDESIGN.md`，在用户明确确认前停止，绝不提前制作 PPT。
- 缺少事实、数据、案例或视觉素材时，skill 要求运行它的 Agent 搜索权威的一手来源；搜索能力本身不是此 skill 的依赖。
- 交付的 `.pptx` 中，文本、表格、图表和形状必须保留为原生可编辑对象；照片和生成插图可以是图片资产。

## 用户场景

1. 用户给出主题，希望 Agent 依次采访、形成可确认的演讲设计，再制作演示稿。
2. 用户给出已有材料，希望 Agent 提炼叙事和设计系统，确认后生成可编辑演示稿。
3. 用户在确认设计后希望修改内容、视觉方向或某几页，skill 使用已保存的 `PPTDESIGN.md` 作为修改依据。

## 设计

### 需求采集

skill 根据输入的完整性选择模式。主题采访模式维护一个已答字段清单，按照“主题和目标、受众、使用场景、核心信息、证据、篇幅、视觉偏好”的优先级逐轮补全，但只提出当前最能减少不确定性的一个问题。原始材料模式先盘点可读材料、事实空白与版权限制；仅在缺少会改变大纲或设计的要素时提出一个问题。

### 事实与素材

用户材料优先。若允许补充且信息不足，Agent 先查权威一手资料，并在设计文档中记录每个外部事实或素材的来源、日期和用途。推断与未核实信息显式标记，不能写成既成事实。图片与其他素材的许可状态同样记录。

### PPTDESIGN.md 契约

每个 deck 在专属输出目录保存 `PPTDESIGN.md`。该文件采用 `design.md` 的“YAML tokens + 可读设计说明”思想，并额外规定：

- 项目目的、受众、叙事与事实/素材来源；
- 画幅、网格、色彩、字体、字号、间距、形状、图表和页脚 tokens；
- 逐页标题、单页结论、内容、版式、可编辑对象、素材槽位与演讲备注；
- 可访问性、可编辑性和验证清单，以及仍待用户决定的项目。

展示时先给出逐页大纲、设计方向、来源和风险，随后等待明确确认。确认前可修改并重新展示该文件。

### 原生 PPTX 生成

生成层采用对象级 PPTX API（首选 PptxGenJS），从 `PPTDESIGN.md` 读取 tokens 和逐页规格，生成文本框、表格、图表、线条和形状。参考项目只贡献需求分析、版式、图片比例与视觉 QA 原则：图片型/HTML 型路线不可作为 PPTX 的最终渲染层。

### 质量门

生成后渲染预览，逐页检查内容缺失、文字溢出、重叠、对比度、网格对齐和图片裁切。再检查 PPTX 内的可编辑对象比例，确保整页没有被扁平图片替代。交付 `PPTDESIGN.md`、`.pptx` 和可选预览文件。

## 验收与测试 seam

1. 静态契约：skill 元数据、模式路由、单问题采访规则、确认门和引用的资源一致。
2. 主题采访行为：模拟请求每轮只出现一个问题，并在用户确认前不会触发 PPTX 生成。
3. 原始材料行为：材料被列为主来源，缺失信息只引发一个高价值问题。
4. PPTX 工件：最小示例生成可打开的演示稿，包含可编辑文字与形状，并能输出可审阅预览。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 长材料导致 skill 上下文膨胀 | 先建立材料清单和摘要，只按页需求读取原文片段 |
| 视觉路线强但不可编辑 | 以原生对象为默认，图像只用于照片与插图，不把页面合成为位图 |
| 搜索资料不可靠或无授权 | 优先一手来源，记录来源/日期/用途，标记不确定或无法确认的信息 |
| 用户在采访时被连续提问打断 | 状态机规定每轮一个问题，回答前不推进 |
