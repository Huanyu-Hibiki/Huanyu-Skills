# sy-practice · 实践转化（卡片 → 书名\知识点 技能）

把"知道"变成"会做"——把书中知识固化为可反复调用的个人技能。

> **知识库根目录 `<知识库根>`**：① 本次会话用户显式指定 → ② 当前 Agent 打开的项目路径下有知识库标志（`阅读笔记/log.md` 或 `阅读笔记/_system/用户阅读报告.md`）→ ③ `~/.shendu-yuedu/config.json` 的 kb_root（问用户是否沿用）→ ④ 默认当前 Agent 打开的项目路径。权威定义见 `01-init/SKILL.md`「知识库根目录解析协议」。

## 前置
1. 读 `<知识库根>/阅读笔记/YYYY-MM/<书名>/知识卡片.md`（#4 全部卡片 C-001…）+ 知识网络图谱。
2. 读 Hub 取核心目标+应用场景。

## 技能定义标准（不达标不算技能）
1. **可触发**：有明确"当…时用此技能"
2. **可执行**：有具体步骤，不是"多读书"这种建议
3. **可验收**：执行后有可观察的"完成信号"
4. **可复用**：不绑单次场景，同类情境能反复调用
5. **原子化**：一技能做一事，复杂流程拆多个并标依赖

## 推理框架（Algorithm-of-Thoughts + CoV + 自校正）

**Step 1 卡片筛选（AoT 过滤）**
- 概念定义且无直接行动 → 不独立成技能，作其他技能的"知识背景"
- 方法工具 → 🔧工具型技能
- 洞察观点 → 🧠思维型技能（决策框架/检查清单）
- 常见误区 → ⚡决策型技能（"当…时，避免…"）
- 行动原则 → 直接转对应类型技能

**Step 2 技能萃取**
- 命名空间：`书名\动词化知识点`（"故事点估算"→"执行故事点估算"；知识点≤10汉字且动词化）
- 触发条件：从卡片 L1/L2 提适用场景，用"当…且…时"
- 步骤拆解：卡片方法→动作序列（每步≤2句，含可观察动作）
- 验收标准：从卡片"行动转化"提可验证结果

**Step 3 依赖与冲突**：A步骤引用B输出→A依赖B；A、B同工作流连续用→组合；A、B触发互斥→冲突。

**Step 4 CoV 四重验证**：①可执行性（不懂此书的人能否仅凭条目执行）②触发条件（太宽泛？真实场景能识别？）③验收（可观察可测量？禁"理解/掌握/熟悉"）④命名空间（格式对？已动词化？）

**Step 5 自校正**：过度抽象→拆可观察行为；步骤遗漏→补过渡；命名冲突→合并或差异化；脱离目标→删或降级"扩展"。

## 🔴 CHECKPOINT · 🛑 落盘前技能清单人审
7 点同步写入前，先向用户展示萃取结果一览表（技能名 / 类型 / 触发条件一句话 / 验收第一条）。用户确认 OK 才执行写入；用户要求增删改时回到 Step 2 调整后重新展示。

## 技能条目结构
```
### SK-001: 书名\执行XX
来源卡片 C-001 · 类型🔧/🧠/🗣️/📋/⚡ · 熟练度目标 初学/进阶/精通
触发条件：当…且…时

#### 执行步骤
1. …（每步≤2句，含可观察动作；复杂拆a/b/c；标关键决策点及判断标准）

#### 验收标准（≥3条，含1条反脆弱标准）
- [ ] 能…（可观察可测量）

#### 常见失败模式（3个，附早期预警信号）
1. 错误：… → 预警：…

#### 关联技能
前置依赖 / 后续组合 / 冲突技能（引用 SK-ID）
```

## 输出
1. **可执行 skill 资产写入 `<知识库根>/skills/<书名>/`**：
   - 单本索引：`<知识库根>/skills/<书名>/INDEX.md`（技能合集 + Mermaid 依赖图谱）
   - 单个技能：`<知识库根>/skills/<书名>/<skill-slug>/SKILL.md`
2. **同步追加到 `<知识库根>/skills/INDEX.md`**（跨书技能索引，⭐核心资产）——按 `书名\知识点` 索引，跨书汇总。
3. **同步回填阅读报告**：`<知识库根>/阅读笔记/_system/用户阅读报告.md` 的「已萃取技能索引（跨书累积）」章节，写入 skill 名称、路径、触发条件、来源书/章节。
4. **同步 Obsidian LLM Wiki 索引**：在 `wiki/index.md` 的手动 Skills/References 区或新建 `wiki/concepts/<书名>-技能索引.md` 中链接到 `skills/<书名>/INDEX.md`，确保后续可被 LLM Wiki 检索/调用。
5. **阅读侧记录仍写回对应书目目录**：`<知识库根>/阅读笔记/YYYY-MM/<书名>/实践转化.md`，记录本次从哪些知识卡片萃取了哪些技能；文件头带 OKF frontmatter（`type: 实践转化` / `title: <书名>·实践转化` / `tags: [深度阅读, <书名>]` / `timestamp`），回填阅读报告/wiki 索引的链接写法遵循 Hub 报告「知识库工具链」的链接规范。落盘后追加 `阅读笔记/log.md` 一条：`## [YYYY-MM-DD] practice | <书名>·萃取X个技能`。
6. 实践路线图（30-60-90天）：Week1-2 只练1个核心技能→Month1 扩2-3个→Month2-3 组合成工作流
7. 与 #3 实践钩子衔接表（每个钩子是否已转为某技能的首次执行）

### 同步失败处理（7 点同步的 fallback，绝不静默）
- 目标文件/目录不存在 → 先创建再写入（INDEX.md 带表头；技能目录带 SKILL.md 模板）
- 阅读报告缺「已萃取技能索引（跨书累积）」节 → 在报告末尾追加该节再回填
- `wiki/index.md` 有手动 Skills/References 区 → 链接进去；无该区但 wiki/ 存在 → 按输出点 4 的备选新建 `wiki/concepts/<书名>-技能索引.md`；wiki/ 整体不存在 → 跳过并在 `实践转化.md` 留一行注记，完成后告知用户
- 任一同步点写入失败（路径不可达/权限） → 🔴 停下告知用户哪点失败，其余点照常；禁止降级为"假装已同步"

## 约束
- **严格命名**：每个技能以 `书名\动词化知识点` 为标题，禁省书名
- **触发必须具体**：禁"需要估算时"，要"当…且…时"
- **验收必须可观察**：禁"理解/掌握/熟悉"
- **反脆弱标准 = 失败可见性**：验收中那 1 条反脆弱标准必须写明"技能失效/做错时会出现什么可观察信号"，让失败自动暴露而非无声无息（例："连续 3 次使用验收未达标 → 触发 #6 进化复盘"；禁写"效果好"式正向空话）
- **禁不可执行建议**："保持开放心态"必须转成"当他人反对时，先复述对方观点再回应"
- **诚实标推断**：步骤/验收基于推断标 `[推断]`
- **数量控制**：卡片>20张时只输出 P0 卡片对应技能，P1 标 `[扩展Skill，待P0熟练后解锁]`
- **不脱目标**：每个技能的触发或验收至少出现1次用户目标/场景关键词
