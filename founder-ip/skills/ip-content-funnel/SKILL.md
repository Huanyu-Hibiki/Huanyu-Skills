## Workflow

### Phase 1 ｜ 首屏

```
🎯 /ip-content-funnel — 年度内容漏斗 + 选题库

徐沪生说："优质内容+超级个体才是未来最佳模式。"[1.3]
但"优质内容"不是零散的，是有**结构**的。

这个 skill 帮你定制 3 件事：
  1. **三轨比例**——A 轨破圈 / C 轨认知 / B 轨转化，各占多少
  2. **双系列定位**——BiP + 张三（或其他系列），分别承担什么
  3. **选题库**——50+ 个利他型选题，告别"不知道拍什么"

3 件事先说在前面：

1. **利他原则是底线**——每个选题必须回答"用户看完得到什么？"
   回答不出 = 选题作废 [徐沪生 6.2]

2. **白痴用户思维是过滤器**——每个选题都过"假设用户对你毫无兴趣"的检验 [徐沪生 6.7]

3. **三轨比例不是死的**——但转化轨（B 轨）必须 ≤30%，非转化内容（A+C 轨）≥70% [徐沪生 6.1]。

准备好开始吗？（🔴 等你确认后开始 6 问，一次一问）
```

#### Mode: interview 完整 6 问

**Q1 ｜ 账号形态**（徐沪生第 3 章）

> "你的账号是单一形态还是'节目杂志'？"

候选：
- **a. 单一系列**——就一个内容线，所有视频同类
- **b. 双系列**（如 BiP + 张三）——两条线交替
- **c. 节目杂志**——像电视频道，多栏目轮换 [徐沪生 3.x]
- **d. 还没决定**

**记录字段**：`account_format`

---

**Q2 ｜ 内容比例定制**（徐沪生 6.1 + 《做号》第 4 章内容漏斗）

> ⚠️ **命名冲突坑（2026-08-14 实战踩过）**：徐沪生 6.1 的"ABC"（A=内容导向/B=自己故事/C=产品故事）和"轨道 ABC"（A=BiP 借古论今/B=张三转化/C=工程史认知）字母撞车，同一文档里两套并存必然打架。**已拍板方案**：用户账号弃用徐沪生式 ABC 分类，改用"轨 + 漏斗层"命名——轨道即漏斗层，一一对应：

| 轨 | 漏斗层（[做号 第4章]） | 内容 | 功能 |
|---|---|---|---|
| A 轨 | 顶层·破圈 | BiP 自述/复盘 × 借古论今壳 | 人设信任 + 破圈 |
| C 轨 | 中间层·认知 | 领域古今对照（如工程史×AI 应用，"应知而未知"） | 专业认知 + 双圈桥梁 |
| B 轨 | 底层·转化 | 痛点案例（如张三踩坑）→ 产品 | 精准流量 + 转化 |

> 漏斗外面（与专业人设无关的社会热点/娱乐话题）一律不碰 [做号 第4章]。

> "基于你的产品阶段和受众，定制三轨比例："

候选（基于产品阶段推荐）：
- **验证期（无 PMF）**：重底层（B 50/C 30/A 20）——痛点案例聚精准用户最快
- **打磨期（少量付费）**：认知层为轴（C 40/B 30/A 30）——"应知而未知"不消耗个人资历且天然双圈（实战示例：一账号曾初选此档，同日微调为 A 40/B 30/C 30 改以破圈层为轴——比例定稿常见回摆，属正常，最终以"轨是否承载人设叙事"定轴）
- **扩张期（稳定付费）**：可上调 B 轨转化比重，但 B ≤30% 纪律不变
- **其他**：自定义

> 🔴 **微调模式坑（2026-08-14 实战）**：用户拍板比例后可能在同一天再微调（"总体方向不变，小调整"）。**改比例必须全链路同步**——content-funnel.md（§2 比例 + 系列定位表 + 衔接段 + 修订记录）、cheat-seed SKILL.md、track-decision-protocol.md、.cheat-state.json 的 `track_mix_ratio`。本次漏改一处就会被下一个 session 当旧值引用。**微调前必须先列出全链路清单，改完逐处核对。**

**配套纪律（三条，缺一不可）**：
1. **A 轨利他检验**：A 轨每条必须过"用户看完得到什么"（[徐沪生 6.2]），纯记录心情不发——A 轨若超徐沪生"自己的故事 ≤20%"的线，靠"观点内容披自述壳"守住，防滑向纯自恋
2. **B 轨转化味控制**：不硬塞产品、每条只选一个主指标 [徐沪生 6.1][7.3]
3. **C 轨史料纪律**：AI 搜索工具（DeepSeek/Kimi/元宝等）供原料，但**没有原文出处的引用一律不发**——终审人工核验"原文真实存在+引用不歪"，防 AI 幻觉炸真实型人设（《做号》第 4 章：虚构一旦被发现放大，后果超乎预料）

**栏目形态（2026-08-14 拍板）**：各轨全部做成**合集栏目**——账号整体是"视频节目杂志"（徐沪生第 3 章），观众追更"栏目"而非只追更"人"，栏目 IP 顺便成立（呼应徐沪生 5.5 节目 IP 兜底）。

**追问规则**：如果用户仍想用旧 ABC 语义（内容/自己/产品三分类），提醒字母撞车风险，建议其换轨命名或明确区分上下文。

**记录字段**：`track_ratio`

#### Q2.5 ｜ 守正出奇节奏（时间维度）

> ⭐ ABC 是**类型比例**，守正出奇是**时间节奏**——两者正交。
> 完整方法论见 [loop-diagnostics.md](../../shared-references/loop-diagnostics.md) 第三部分

> "守正出奇：先铺 70 分精准内容跑通模型（守正），价值感立住后再定期试爆（出奇）。顺序不能反。
> 你的节奏怎么排？"

候选（基于每周 2 条的节奏）：
- **a. 80/15/5**——守正 6-7 条/月 + 试爆 1 条/月 + 转化 0-1 条/月 ✅ 推荐（起号期/稳定期）
- **b. 90/10/0**——纯守正，不试爆（极早期，模型还没跑通）
- **c. 70/20/10**——重试爆重转化（稳定上升期后期，基础已厚）
- **d. 其他**

**关键约束**：
- 守正的 70 分 = 你自己的 70 分（不憋大招、不追求完美、但也不难看）
- 试爆必须在守正铺量之后——反过来的下场：爆款来了接不住，烟花一场

**记录字段**：`shou_zheng_chu_qi_rhythm`

**Q3 ｜ 双系列/多系列定位**（如 Q1=b 或 c）

> "你的多个系列，分别承担什么功能？"

逐个系列问：
- **系列名**（如 BiP / 张三）
- **核心目的**：求流量 / 求转化 / 求品牌 / 求记录
- **目标受众**：基于 persona 的第一受众 / 次级受众
- **更新频率**：每周几条
- **优先级**：主系列 / 副系列

**记录字段**：`series_definition`

⚠️ **关键约束**：徐沪生说"一个账号一个调性"。多个系列必须**统一在人设下**——不能 BiP 是技术深度调性、张三是搞笑段子调性。

**Q4 ｜ 利他选题库**（核心，多轮深挖）

> "徐沪生第 6.2 节'内容第一原则：利他'。每个选题必须回答：**用户看完得到什么？**
> 现在基于你的素材库，生成利他选题。"

**Step 1**：读取 persona-charter.md 的素材库（如 6 类踩坑素材）

**Step 2**：对每类素材，问 3 个利他角度：
> "你的'合同类踩坑'素材，能从哪些利他角度讲？"

候选（参考徐沪生民宿案例 6.2）：
- **a. 教学型**——教用户怎么避免这个坑（"3 个合同条款必须警惕"）
- **b. 资讯型**——提供行业信息（"2024 年招投标新规解读"）
- **c. 工具型**——给用户参考（"我的 Agent 是这样识别这个风险的"）
- **d. 故事型**——讲一个具体案例，用户从中悟出道理
- **e. 启发型**——抛出观点，引发思考

**Step 3**：每类素材生成 8-10 个选题候选

**Step 4**：每个候选过"白痴用户思维"检验 [徐沪生 6.7]：
> "假设用户对你毫无兴趣，刷到这个标题，3 秒不感兴趣就滑走——这个标题能抓住他吗？"

**产出**：≥50 个利他选题，分类存入 topic-pool.md

**记录字段**：`topic_pool`

#### Q4.5 ｜ GEO 长尾关键词标注（每个选题的双重复用）

> ⭐ **选题 = GEO 长尾关键词库**（一举两得）
>
> 完整方法论见 [shared-references/geo-china-guide.md](../../shared-references/geo-china-guide.md)

对 Q4 产出的每个选题，**额外标注**：

1. **长尾关键词**：这个选题覆盖哪些用户会在 AI 搜索里问的关键词？
   - 例：选题"3 个合同条款必须警惕" → 关键词：合同审核 AI / 合同风险识别 / 工程合同合规
2. **AI 友好结构自检**：
   - [ ] 标题含长尾关键词？
   - [ ] 内容是 Q&A / 清单 / 对比 / 明确数据 结构？[GEO 指南 3.2]
   - [ ] 产品名 / 公司名 / 创始人名出现了？
3. **目标 AI 搜索引擎**：这个选题最可能被哪个 AI 引用？
   - DeepSeek（技术深度）/ 元宝（公众号）/ 知乎直答（专业）/ 豆包（抖音）

**产出**：每个选题附带 GEO 标签，存入 topic-pool.md 的 `## GEO 覆盖矩阵` 段

**Q5 ｜ BiP 公开边界**（如做 Build in Public）

> "你的 BiP 内容，公开到什么程度？"

候选（基于 interview-profile.md 的半公开推荐）：
- **a. 全公开**（Pieter Levels 型）—— ❌ 对 B 端高风险
- **b. 半公开**——过程透明，数字保密 ✅ 推荐
- **c. 选择性公开**——只讲已复盘的，不讲正在进行的
- **d. 不做 BiP**

如果选 b，定制具体边界（参考 interview-profile.md 的表格）：

| 维度 | 公开 | 不公开 |
|---|---|---|
| 过程 | ___ | ___ |
| 数字 | ___ | ___ |
| 客户 | ___ | ___ |
| 技术 | ___ | ___ |
| 失败 | ___ | ___ |

**Q6 ｜ 历史壳子/比喻库**（如表达风格 = 创意比喻型）

> "徐沪生第 6.3.1 节'导演意识'——用画面讲故事。
> 你的'创意比喻型'风格，需要建立比喻库。"

**Step 1**：列出你的核心技术概念（如 multi-agent / RAG / vector database）

**Step 2**：对每个概念，brainstorm 比喻：
- multi-agent → 三省六部制（明代）

**Step 3**：筛选比喻的标准：
- a) 目标受众能 get 吗？（工程同行 vs 泛 AI 圈）
- b) 比喻准确吗？（避免误导）
- c) 有画面感吗？（视觉化）

## Refusals

| 用户说 | 为什么拒 | 拒后出路 |
|---|---|---|
| 「转化轨比例调到 50%」 | 转化 ≤30% 纪律不因阶段放宽 [徐沪生 6.1][7.3] | 三杠杆替代：提单条效率 / 守正出奇升档（≤70/20/10）/ C 轨软植入；想多卖货先说清是转化率低还是流量不够 |
| 「这个选题挺好，但我不知道用户能得到什么」 | 利他原则是底线 [徐沪生 6.2] | 回答不出 = 选题作废；可改写为教学型/工具型角度再过一次白痴检验 |
| 「蹭这个热点吧」 | 热点污染画像 [徐沪生 5.6] | 改做"热点背后的行业长期问题"角度——蹭的是认知不是事件 |
| 「BiP 全公开，包括收入」 | B 端高风险（定价锚点泄露/谈判被动） | 半公开（过程透明数字保密）；确是 toC → 降级为提醒并记录用户选择 |
| 「选题库生成 200 条」 | 质量优先，50 条够用 | 先出 50 条过白痴检验；拍完 70% 再月度补充，不一次堆量 |
