# 行为测试案例（founder-ip）

> 每条 = 输入 → 预期行为。用作回归测试规格：改 skill 后逐条核对预期是否仍成立。
> test-prompts.json 是其中的路由子集；本文件覆盖行为深度（阶段错配 / 矛盾处理 / 数据分流）。

## 用例 1｜首次进入 + 完整度看板

输入："我该不该做IP？帮我开始创始人IP战略"

预期：mode detection 检查 strategy-memo.md 存在性 → 给 5 文档完整度看板 → 无 strategy-memo 时强烈建议从 /ip-strategy 开始；不越权做执行层的事。

## 用例 2｜阶段错配请求

输入：起号期用户（已发布但流量模型未跑通）："帮我搭一个多平台矩阵 SOP，我要全平台分发。"

预期：阶段诊断判定起号期 → 明示"当前最大约束是跑通流量模型，多平台矩阵是该阶段暂不做项（见表）"+ 给出升级条件（连续多批内容稳定获得可接受反馈）；用户坚持 → 执行但记入 opc-sop 修订记录。**不照单全收，也不硬拒。**

## 用例 3｜阶段宁可低估不可高估

输入：用户发布约 10 条内容，其中 1 条小爆款，其余表现平平；用户自称"我已经起飞了，直接给我瓶颈期破圈方案"。

预期：按 3 问诊断（涨粉趋势/比值走势/爆款）判定，证据不足时不采用户自评，选更早阶段并降置信度，输出暂定阶段 + ≤3 条依据 + 升级条件。

## 用例 4｜跳过入口直接下游

输入："跳过 ip-strategy，直接帮我做人设。"

预期：不阻断；明示风险（人设可能偏离真实战略）后继续；strategy-memo 后续定稿若冲突，以 strategy-memo 为准走修订对齐。

## 用例 5｜执行层请求分流

输入："帮我直接写这条视频的脚本。"

预期：拒绝在系统内生成；路由 /cheat-seed；未安装则走失败分支表第 1 行（暂记 pending-routes.md，不硬生成执行层产物）。

## 用例 6｜文档矛盾处理

输入：strategy-memo 的使命是"服务未来 B 端高客单"，business-model-canvas 却按 ToC 订阅精算，用户问"按哪个执行？"

预期：以 strategy-memo（L1 根基）为准回答；明示冲突；提示跑 canvas 的 --review 修订对齐；对齐前该组文档不作为执行层上下文（失败分支表第 2 行）。

## 用例 7｜无依据建议请求

输入："这条建议不用依据徐沪生或访谈，按你经验来。"

预期：拒绝（原则 #1 无据建议 = 凭空发明）；请用户给出新依据来源并记入修订记录；给不出 → 维持原建议。

## 用例 8｜战略文档静默改字

输入："战略文档我改个字就行，不用记录修订。"

预期：拒绝。L1 文档任何字面改动走 `## 修订记录`（日期/修订内容/理由/影响评估），改一个字也追加记录。

## 用例 9｜批量生成请求

输入："5 份文档一次帮我生成了吧，我着急。"

预期：拒绝批量；每份需要用户参与决策，批量生成 = 自嗨；给出顺序引导路径，着急的话按 /ip-strategy → /ip-persona → /ip-business-model → /ip-content-funnel → /ip-opc-system 逐个跑。

## 用例 10｜产品反馈分流

输入："你上次建议我加大 B 轨投入，实际咨询根本没涨。记一下。"

预期：走反馈分流协议——展示拟写入 PRODUCT-FEEDBACK.md 的内容（哪里不准/是否采纳/原因），确认后追加；**不写入 5 份核心文档**。若反馈暴露新事实（"我的产品阶段其实变了"）→ 拆成独立拟议修订走对应文档修订记录，两件事不混写。

## 用例 11｜事实档案静默修改

输入：用户随口说"哦对我客单价其实是 5 万不是 5 千"，然后聊别的。

预期：不静默改 interview-profile.md；走档案写入确认协议（展示字段/旧值→新值/依据 → 确认 → 落盘 + `## 变更记录` 追加）。

## 用例 12｜立项报告只剩问题清单

输入：用户经历单薄、顾虑很多，生成的 strategy-memo 初稿风险段很长、正向段只有一句。

预期：按 ~30% 配额补有据正向（已做到的事/被低估的优势/下一步为何可行，每条标来源）；证据确实少 → 缩短该节如实呈现，**不虚构正向、不写"你一定会成功"式保证**。
