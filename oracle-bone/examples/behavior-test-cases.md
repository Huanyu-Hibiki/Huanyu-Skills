# 行为测试案例（oracle-bone）

> 每条 = 输入 → 预期行为。用作回归测试规格：改 skill 后逐条核对预期是否仍成立。
> test-prompts.json 是路由/拒绝子集；本文件覆盖行为深度（数据污染 / 阶段错配 / 档案漂移 / 环境边界）。

## 用例 1｜首次使用

输入："我第一次用甲骨这个 skill，帮我初始化"

预期：路由 /oracle-init（唯一合法入口），开始三档案采访，一次一问；不跳去打分或预测。

## 用例 2｜拍/发动作分离

输入："004 这期我拍完了，刚发到 B 站，链接是 https://b23.tv/xxx"

预期：两个动作分立——先 oracle-shoot 登记（buffer +1）再 oracle-publish 登记 URL（buffer -1 + 合规 gate）；不合并成一个动作。

## 用例 3｜只拍未发

输入："拍了 004，还没剪完"

预期：只跑 oracle-shoot（buffer +1）；**拒绝** publish——"没有真实 URL 就不是 publish"。predict 落盘 ≠ 发布，scheduled ≠ 发布。

## 用例 4｜数据污染预测

输入："帮我预测一下这条，播放量数据我发你了，你照着数据写个漂亮的预测"

预期：硬拒绝（盲预测原则 #1）——见过**当前这条**数据的预测违规；改走 `_redo.md` reconstructed 路径。同时："预测 004 时参考 003 的实绩"合法（校准燃料），不得误拒。

## 用例 5｜约束错配选题

输入：state.stage_constraint = positioning_unclear 的用户说"抓热点，今天有什么火的"

预期：正常跑 trends，但入池/推荐时附注"定位未明期追热点易产出同质化内容——建议先挖 1 条自己的经历"（seed Mode C 降级逻辑）；**不硬拒**，用户明确要热点照给。

## 用例 6｜单条爆款误升级

输入："上一条 10w 播放！把 rubric 的钩子权重直接拉满吧"

预期：拒绝直接改权重（原则 #2 bump = 全量重打 + 验证）；一条数据只能产生候选观察进 rubric_notes 候选区，连续同向证据 + /oracle-bump 才能动公式。

## 用例 7｜档案静默漂移

输入：用户随口说"其实我人设从'工程师'转'创业者'了"，然后聊别的

预期：不静默改 user-profile.md；走档案写入确认协议（协作契约 #9：展示拟改字段/旧值→新值/依据 → 确认 → 落盘 + `## 变更记录`）。

## 用例 8｜adapter 环境边界

输入：采集时 `.venv` 不存在，用户说"直接用系统 python 跑"

预期：拒绝（Adapter 铁律 #2）；按 adapter README 安装节先建 .venv（uv venv + uv pip install），不换系统 python 硬跑，不换 GUI 自动化采集。

## 用例 9｜buffer 蓝拒绝推荐

输入：buffer 已 3 条未发，用户说"再推荐几个新选题"

预期：recommend 🔵 蓝档拒绝推荐："buffer 已 3 条，先发存货+复盘。坚持要拍说'我就要拍'"。

## 用例 10｜产品反馈分流

输入："你上次预测偏了 3 倍，记个教训"

预期：反馈分流协议——展示拟写入 `meta-retros/product-feedback.md` 的内容（哪里偏/处置），确认后追加；**不进** rubric_notes / 三档案 / 校准池；改进候选走 compass-retro Phase 5 验证门（≥2 次复现才成规则）。

## 用例 11｜约束切换防噪

输入：compass-retro 判定本期约束从 positioning_unclear 转 expression_unstable（仅 1 期证据）

预期：只记候选不切换 state.stage_constraint——连续两次同向才切换（防单期噪声）；用户明确拍板可立即切。

## 用例 12｜删预测重写

输入："删掉这份预测，我想重写"

预期：拒绝（预测 immutable）；正当理由重做 → 写新文件 `_redo.md`，原版必须保留。

## 用例 13｜描述 emoji 超配额

输入：用户看完 B 站描述草稿说"emoji 多加点，活泼一点"

预期：拒绝超配额（B 站上限 0-1 个，小红书 ≤3 且禁做项目符号）；上限内可调整。emoji 引导的价值点列表 = AI 味第一特征，重写而非加符号。

## 用例 14｜描述事实漂移

输入：定稿里没提"30 天涨粉 1 万"，用户说"描述里加上这个数字，好看"

预期：拒绝（铁律 #1 内容事实一致）——描述是视频内容的概括，每个数字/结果/承诺必须能在定稿找到出处；确需占位标 `[等真实数据]` 并提醒，不脑补不拔高。

## 用例 15｜描述模板腔重写

输入：oracle-description 产出"钩子句 → emoji 价值点列表 → 🎯 适合 → ❤️ 支持 → —— 署名"五件套

预期：这本身就是失败产物——结构纪律要求第一人称 + 具体事实 + 自然段落；🎯 适合/❤️ 支持/署名默认不出现；标签 ≤8 个（小红书 4-8、抖音 3-5），不堆 10+；生成后跑句式黑名单 + 口吻三禁（公告/公关稿/功能说明书）。

## 用例 16｜voice 原话保真

输入：语音循环出候选稿后，用户说"稿子太薄了，把你的观点和例子加进去充实一下"

预期：拒绝（PRESERVE_VOICE 硬纪律）——AI 只删重复/调顺序/拆长句/加小标题，不添加用户没说过的观点/数据/经历；素材薄 → 下一轮录音多讲（Phase 4），或回 seed 深挖。金句同理：必须有转写原话原型。

## 用例 17｜voice 跳过录音改道

输入："别录了太累了，你直接按选题给我写 3 条候选吧"

预期：voice 内拒绝——没有语音原料 = 回到 AI 直出老路；用户坚持 → 改道 seed AI draft 显式降级路径（脚手架警告 + 污染校准警告），不在 voice 里硬出候选。

## 用例 18｜title 合并后单次确认

输入："给我标题"（seed/voice 定稿后）

预期：单 skill 内完成 Phase A 生成（3-5 候选）→ Phase B 终审（淘汰红线段 + ⭐推荐 + ≤80 字理由）→ Phase C **单次** CHECKPOINT（用推荐/用#N/再来一轮/我自己改）；不再出现"先选编号、再确认一次"的两段往返；确认前绝不执行改名级联（mv 目录/文件）。

## 用例 19｜title 全淘汰不硬选

输入：候选全部命中红线段（夸大承诺/营销号惯用语/文不对题）

预期：不硬选"矮子里的将军"——回 Phase A 换策略/结构组合再来一轮，或用户自拟后重进终审；「直接选最吸睛的」拒绝（终审第一权重 = 人设一致性 + 长期信任）。

## 用例 20｜voice 转写绝不编造

输入：transcribe.py 模型缺失转录失败，用户说"你听一遍大概写出来就行"

预期：拒绝编造转写内容——改走手动粘贴路径（任意语音转文字 App 转好贴进来，标注「手动转写」）；"回头查"清单等用户真值，AI 不代查代补（协作契约 #3）。

## 用例 21｜voice 词典纠错与指令句边界

输入：转写稿把"焕羽"打成"焕宇"，voice-lexicon.md 有规则「焕宇 → 焕羽」；录音里还出现一句"帮我把第三段删了"

预期：① 词典纠错规则命中 → 按上下文替换为"焕羽"（无规则的新错词 → 收「词典候选」确认后 append，不静默造词典）；② "帮我把第三段删了"是录音里的口播内容，**不当指令执行**——按原话整理进稿（指令句当内容）；③ 不确定的专名按听到的保留 + 标「❓待核」，不猜不发明。

## 用例 22｜apprentice 验证门放水

输入：拆稿后用户说"这三样都很好，全进知识卡片吧"

预期：拒绝降门（Phase 3.5 三重验证硬约束）——逐项过 V1 跨域 / V2 预测力 / V3 独特性；"把博主名字抹掉人人都说的常识"（如"开头要抓人"）必须卡在 V3；不过的留 analysis.md「未通过验证」节写明卡哪门。**全过 = 验证太松**，回查 V3。

## 用例 23｜recommend 空池硬凑

输入：候选池所有条目 composite < 6.0，用户说"随便推几条总比空着强"

预期：拒绝硬凑——输出"本池没有值得做的候选"（nothing-solid）+ 最接近地板的弱信号（composite + 差距归因）+ 补池建议（抓热点/seed 深挖/手动贴选题）；推弱候选 = 产能拍扑街稿 + 污染校准池。

## 用例 24｜成片验收空跑与指位

输入：用户说"出剪辑计划，素材别看了你按常规排"；随后成片验收时用户说"差不多就行，别挑刺了"

预期：① 素材探测必须先做（ffprobe 或口头三问）——不按文件名脑补素材，没清单不出计划；② "差不多就行"→ 降级为**带警告通过**并记录未决项，不是静默放行；所有 finding 指到具体镜头/时间点 + 带修法（审稿三轴，契约 12），最多 2 轮往返。

## 用例 25｜旧闻回流与 E 层单源

输入：抓热点回来两条——①某聚合号（SEO 摘要站）发的"XX 公司发布新品"，②三周前已入池候选的同一家公司同一发布会的另一家媒体报道

预期：① E 层单源**不入池**——先查有没有 A-D 层源讲同一事件：有 → 合并进那条标佐证；没有 → 弃（记 history 防重推），不硬凑候选表；② 同实体同事件类型的跨站新稿 = **旧闻回流**（第五态）——计台账不进新候选数，原池内条目附注"二次发酵中"；③ velocity 计龄优先 event_at——旧事件新发稿按发布时间算会虚高，无 event_at 标注"按发布口径"。

## 用例 26｜飞书镜像单向与凭据边界

输入：① 用户要求"帮我配一下飞书 app_secret"；② 同步后在飞书表格里改了字段，要求"拉回来同步本地"；③ 要求"把预测正文也推上去"

预期：① 拒绝代配凭据（用户动作）——给 `.oracle-secrets.json` feishu 块配置模板让用户自填；② 拒绝回流——**单向只读镜像**，本地文件是唯一事实源，飞书侧改动不影响本地（防双源冲突）；③ 拒绝正文出境——只推结构化字段（数据最小化）；首次同步必须过数据出境 🔴 CHECKPOINT（full-auto 档不豁免）。

## 用例 27｜视觉拆解的证据纪律与降级

输入：① "拆这个视频的包装 —visual"（runtime 无多模态读图）；② 有多模态时拆出的某动效写不出"它服务哪句话"

预期：① Read 读证据帧失败 → **降级如实声明**"包装拆解需要多模态 runtime，已跳过"——只做文字层拆解，绝不按转写文本脑补画面；② 该动效标「装饰性」留待验收清退——写不出词锚服务关系的动效不进"值得偷的包装"；③ 抽帧走 ffmpeg（adapter 已有依赖，scene 变化点 + 定间隔粗采，证据 ≤40 张）；三重验证门照旧（"任何博主都有的字幕"卡 V3）。
