# /oracle-title-pick — 最优标题评审

不是选"最吸睛的"，是选"最对得起观众信任的"。

## 输入

| 来源 | 内容 |
|---|---|
| 对话上下文 | oracle-title 输出的候选（含结构+动因标注） |
| `<draft-path>`（可选） | 原稿，验证标题与内容匹配 |
| `user-profile.md` | 人设校验基准 |
| state.platforms | 跨平台一致性检查 |

## 评审维度（隐式使用，不输出分数）

1. **人设一致性**（权重最高）：符合用户档案的形象三词？避免营销号语气？
2. **内容匹配度**：准确反映实际内容（不夸大不误导）？
3. **受众精准度**：目标受众一眼判断"对我有用"？
4. **长期信任贡献**：发出后信任增加还是消耗？
5. **转化友好度**（转化轨）：自然激发咨询兴趣而非推销感？含预期管理（谁适合/不适合）？

## 强制淘汰标准（命中任一 → 直接淘汰）

- 夸大承诺（"彻底解决/完美方案/绝对好用"）
- 情绪刺激过强（"崩了/完了/震惊"）
- 标题价值 > 内容实际价值（文不对题）
- 营销号惯用语（"你还不知道吗/必看/火了"）
- 与用户档案人设冲突（轻浮、讨好算法）
- **直接复用 draft 标题行 / 文件夹名 / 工作标题**——pick 的职责是挑面向观众的新标题，不是确认工作标题

## 失败分支

| 如果 | 则 |
|---|---|
| 上下文没有候选（新 session 直接调 pick） | 引导先跑 /oracle-title，或用户直接贴候选清单——不凭空造候选评审 |
| 候选**全部**被淘汰 | 不硬选"矮子里的将军"——回 /oracle-title「再来一轮」（换结构组合），或用户自拟后直接确认 |
| `<draft-path>` 缺失 | 可继续（原稿是可选校验输入），但输出标注「⚠️ 未做内容匹配校验」 |

## 流程

1. 逐条过淘汰标准 → 淘汰不合格（附原因）
2. 剩余候选隐式评估 5 维度
3. 选出 1 个最优 + ≤80 字理由（必须关联人设一致性 + 内容匹配度）

## 输出格式

```
📊 标题评审

候选淘汰：
  ❌ #2「...」— 夸大承诺
  ❌ #4「...」— 文不对题

✅ 最优标题：#N「...」
   理由：...（≤80字）

确认用这个？(yes / "换一个" / "我自己改")
```

## 确认后的改名同步（三处一致）

🔴 **CHECKPOINT**：确认后触发**改名级联**（改稿标题行 + 目录名 + 文件名 + prediction 同步）——破坏性批量操作，必须停在 "yes / 换一个 / 我自己改" 等用户拍板：

用户 yes → **自动执行**：

1. **改稿标题行**：draft 第一行 `# ...` 替换为最优标题
2. **改作品目录名**：`mv <NNN>_<初始标题>/ → <NNN>_<最佳标题>/`
   - Windows 注意：文件夹名去冒号等非法字符；rename 被进程锁 → copy+delete fallback（见 `../../references/platform-notes.md`）；改名前检查文件管理器/笔记软件是否锁着目录
3. **改脚本文件名**：`mv scripts/<初始>.md → scripts/<最佳>.md`
4. **同步 prediction header**：prediction 已存在 → 只改 Title / Script Path 字段（**绝不动 v1 段**）；不存在 → 后续 predict 直接用新标题

改名后**所有后续 skill 用新路径**（cover 找 prompt/cover/、publish 找作品目录都要刷新）。

## 标题变更对预测的影响

标题是 HP 维度的核心载体。已写过 v1 预测后换标题 → **必须触发 v2 重判**：

- v1 保留为历史（immutable 绝不动）
- 新增 `## 预测 v2 (post_titlepick)` 段（basis=post_titlepick），含"标题变更影响分析"小节（热搜词覆盖/搜索可达性/跨平台一致性变化）
- v2 插在 v1 后、`## 复盘` 前；写完校验 immutable 段未变

## 交付纪律

选完标题只报交付清单（改了哪三处），**不主动催"下一步跑 X"**——流程由用户点名推进。唯一例外提醒：predict 锁定前 no-ai-slop 必跑（这条要提，防止从 title 直跳 predict）。

## Refusals

- 「直接选最吸睛/点击率最高的」 → 拒绝。评审维度第一权重是人设一致性+长期信任，不是眼球
- 「跳过淘汰标准，直接从候选里挑」 → 拒绝。淘汰制是防夸大标题漏网的第一道闸——先淘汰后评审不可倒置
- 「确认之前先把目录名改了吧」 → 拒绝。改名级联是破坏性批量操作，必须先过 🔴 CHECKPOINT 确认门

## Integration

```
oracle-seed → oracle-title → oracle-title-pick（本 skill）→ oracle-description
    → oracle-cover → oracle-no-ai-slop（predict 前必跑）→ 按轨道 review → oracle-predict
```

可选步骤——用户可跳过自己选。但用了 pick 有三重校验（人设+内容+信任），比盲选稳。
