# /oracle-description — 多平台发布文案生成器

## 🔴 两条铁律（🛑 STOP：违反即重写，用户要求打破也拒绝）

1. **内容事实一致**：描述是视频内容的概括，与视频实际内容表述一致。文案里每一条信息（数字 / 结果 / 功能 / 流程 / 承诺）必须能在定稿正文找到出处。定稿没有的：不写、不脑补、不"顺手拔高"；确需留空 → 标 `[等真实数据]` 并提醒。
2. **反 AI 味**：emoji 配额制 + 禁模板腔。真实创作者的描述几乎不用 emoji、不堆感叹号、不搞"钩子→价值点→适合→CTA→署名"五件套。生成后自检：把文案混进一排真人描述里，违和 = 失败 = 重写。

## emoji 配额（硬上限）

| 平台 | 上限 | 用法 |
|---|---|---|
| B站 / 视频号 / 公众号 / 抖音 | **0-1 个** | 默认不用；仅当符号承担真实功能（如分隔链接）时用 |
| 小红书 | **≤3 个** | 只在句尾点缀，**禁止做项目符号** |

- 禁止 emoji 引导的价值点列表（每行挂 ✅🔍📦 之类 = AI 产物第一特征）
- 情绪靠语气词和具体事实传递（"太可爱了！""收藏一下！"），不靠符号装饰

## 结构纪律（替代固定模板）

废料五件套结构（钩子句 / 价值密度区 / 🎯适合：/ ❤️支持：/ —— 署名）。真实描述的样子：**第一人称 + 具体事实 + 自然段落**。

- **开头** = 从定稿最强事实里来的第一句（真实烦恼 / 意外发现 / 明确收益 / 直接讲这期干了什么）
- **中间** = 这期视频实际会讲什么——3-5 个具体点；可用 `1. 2. 3.` 编号或自然段，每点可回溯定稿
- **结尾** = 最多一个自然互动或行动提示（按 CTA 策略表）；署名 / 频道名默认不写

**句式黑名单**（命中即重写）："纯纯干货" / "建议收藏"连发感叹号 / 排比三连 / 每句感叹号 / "还在纠结 XX？" / 课程目录式罗列（"安装、配置、进阶"这种无信息词串）/ 空话形容词连发（强大、惊艳、颠覆、赋能）

**口吻三禁**：公告腔、公关稿腔、功能说明书腔。用"我"不用"我们"（除非档案明确是团队）；不夸大承诺、不贩卖焦虑；关键词自然出现即可，不刻意堆。

## 输入

| 来源 | 内容 |
|---|---|
| `<draft-path>` 定稿 | 正文全文——**事实清单一唯一来源** |
| 已确认标题 | oracle-title-pick 或用户确认 |
| `user-profile.md` | 频道名/人设/变现方式（决定 CTA 策略） |
| `content-plan.md` | 该轨定位（流量轨 vs 转化轨的 CTA 差异） |
| state.platforms | 平台集（每平台一份） |

## Workflow

1. 读输入（定稿全文 / 确认标题 / user-profile / content-plan / state.platforms）
2. **标题核对**：无确认标题 → 🔴 停下问，不拿工作标题顶替；state.platforms 为空 → 问平台集，不默认全平台
3. **事实清单**：从定稿提取 3-5 条最强事实（这期实际做了 / 讲了什么，带定稿出处）——后续所有平台文案只从这个清单取材
4. 逐平台生成（结构纪律 + emoji 配额 + 平台字数）
5. **三重自检**：① 事实核对——逐句回溯定稿出处，找不到的删掉或标 `[等真实数据]`；② emoji 计数——逐平台数，超配额删；③ 句式黑名单 + 口吻三禁扫描
6. 标题一致性核对：文案引用的标题词与选定标题一致——不一致标 `description_title_mismatch` 修正
7. 🔴 CHECKPOINT：展示全部平台文案 → 用户 yes / 「改 X 平台」/ 「重来」
8. append 到定稿 `## 发布文案` 段——已存在该段 → 走 Rerun 协议替换，不追加第二份

## 平台格式规范（字数为纲，结构自由；未列出的平台按最近似平台适配）

### B 站类长简介平台（170-260 字）
- 2-4 个自然段，第一人称讲"这期我做了什么、你会看到什么"
- **具体优先**：写"从安装到生成全身图完整跑了一遍"，不写"全流程详解"
- 编号列表可用（1. 2. 3. 罗列具体用途是真人常用形态）
- 链接给完整 URL（不是"评论区见"）

### 小红书类（100-150 字）
- 首句可反差钩子；emoji ≤3 且只在句尾；标签 4-8 个真实相关词

### 抖音类短简介平台（50-80 字）
- 极短，第一句就是钩子；标签 3-5 个；可加"结尾高能"引导完播

### 微信/视频号类（80-150 字）
- 语速稳重，避免强钩子；重视"朋友圈转发"语境——让转发者读得懂有获得感；链接给完整 URL

### 公众号/Substack 类长文平台
- 摘要式：核心论点 + 适合人群 + 阅读预期

## 标签纪律

- 只写与定稿内容真实相关的词 + 用户档案已有的活动标签；不自动发明热点标签
- 每平台 **≤8 个**（小红书 4-8 / 抖音 3-5），宁缺毋滥——不相关标签 = 误导流量 = 完播率反噬

## CTA 策略（整个描述只保留一个主 CTA）

| 类型 | 流量轨 CTA | 转化轨 CTA |
|---|---|---|
| C 端产品 | 三连+关注（选一为主） | 体验链接 + 咨询入口 |
| B 端服务 | 关注+评论区讨论 | 私信合作 + 案例链接 |
| 暂不变现 | 关注+评论+转发（选一为主） | —（转化轨不存在时） |

## 输出 + 落盘

```
📋 发布文案（标题：<确认标题>）

─── B站 ───
...
─── 小红书 ───
...
（按 state.platforms 逐平台）

直接用？(yes / "改 X 平台" / "重来")
```

用户 yes → **append 到定稿末尾**（不建独立文件，文案永远跟脚本绑定）：

```markdown
---

## 发布文案（由 oracle-description 生成）

### B站
...
### 小红书
...
```

用户"改 X" → 只重写该平台 → 更新对应段。

## Rerun 协议（改稿后重生成）

稿子经 review 改稿新增关键内容后重跑本 skill：
1. **只替换既有 `## 发布文案` 段**——不在末尾追加第二份
2. 后面已有 `## 置顶评论` / 预测段等产物 → 保留不覆盖，替换范围截止到下一个 `---` 二级标题前
3. 新增正文价值点同步进文案；字数超限先压缩再落盘

## Refusals

- 「emoji 多加点，活泼一点」 → 拒绝超配额。emoji 超量是 AI 味第一特征；上限内随便调
- 「把描述写得炸一点」 → 拒绝。描述是内容概括不是标题党——夸大描述推高跳出，伤的是完播和信任
- 「定稿里没这个数字，但你先写上」 → 拒绝。铁律 #1；要写先标 `[等真实数据]`
- 「把抖音文案直接复制到 B 站」 → 拒绝。平台规范不同，逐平台生成本 skill 存在的理由
- 「跳过标题一致性核对」 → 拒绝。观众发现"标题骗我"是信任损耗，核对成本一秒

## Scope 边界

- 交付物**只有**发布文案（append 到定稿末尾）
- **不生成封面 prompt**（oracle-cover 的活）；不生成置顶评论（oracle-pinned-comment）
- 交付后只报交付清单，不主动催下一步

## Integration

```
oracle-title-pick → oracle-description（本 skill）→ oracle-cover
    → oracle-no-ai-slop（predict 前必跑）→ 按轨道 review → oracle-predict
```

可选步骤——用户可自己写。但用了之后跨平台一致性更好（核心信息统一，语气各自适配）。
