# /oracle-study — 对标学习

这是一个学习入口，不是复制器，也不是制作入口。先问清用户想得到的结果，再选择最轻的模式：

| 模式 | 学习单位 | 主要问题 | 最小交付 |
|---|---|---|---|
| benchmark | 账号或一组作品 | 哪些公开产出信号值得作为参照？ | 定性 benchmark 与未验证的模式线索 |
| practice | 一条作品、文稿或机制 | 我能否复述、质疑、迁移，并在自己的轨道做一次最小练习？ | 通过验证门的知识卡片 |
| dual | 同一对象的账号 + 单条样本 | 参照信号与可实践机制是否能被分开记录？ | 独立的 benchmark 与 practice 产出 |

## 共同边界

### 先确认目标结果

输入可以是账号、作品、工作流或机制，但不能把“我想学”当成目标。先用一句话确认这次交付是：

- 只评价公开样本的表现与用户印象；
- 只把一条材料拆成可练习的机制；或
- 在同一份素材归档上同时做两件事。

如果缺失的信息会改变模式，只问一个问题；不因信息不全自动展开长链。只分析可观察的公开产出、数据和机制，不推测创作者的私生活、动机或未公开能力。输出明确区分：已知事实、用户经验、AI 推断、待验证假设。

### 产出 / 机制 / 资产三层

每次学习都把内容分三层，避免把相关性写成因果：

1. **产出**：标题、开场、结构、表达、互动、公开表现数据等可观察结果。
2. **机制**：从产出中提出的、带证据和边界的解释；统计关联不自动成为可复制机制。
3. **资产**：样本归档、分析记录、benchmark 信号、知识卡片和最小实践登记。

缺证据的判断标记为“未证实”，不补写、不脑补。对标只借结构、决策逻辑与视觉逻辑，不复制原人物身份、品牌、Logo、水印或原文案。

### 共享素材归档

三种模式共用以下源目录；它是可读的证据底座，不是把旧目录静默搬家的借口：

~~~
study/<对象>/
├── samples/<content-id>/
│   ├── source.md       # 用户提供的文稿、链接、元数据或手动转写
│   ├── meta.md         # 公开来源、日期、表现数据、证据状态
│   └── analysis.md     # 单条分析；事实、推断、质疑与边界分开
├── benchmark.md        # 账号级样本、印象与定性参照信号
├── techniques/         # 通过三重验证门的知识卡片
└── packaging-learning/ # 仅存已有兼容档案的读取说明；新视觉工作交给 VPW
~~~

只在用户确认后写入学习档案；首次迁移旧目录前先展示影响、来源和目标位置，等待确认。新写入统一采用上述 oracle-study 结构。

### 对项目根主档的同步边界

- `study/<对象>/` 是证据与过程档案，保留来源、样本、质疑和验证链，不替代项目根主档。
- `benchmark` 用户确认后，把跨对象、仍标记 `Imported, untested` 的定性信号汇总到项目根 `benchmark.md`，并保留对象级来源路径；不得直接改 `rubric_notes.md` 权重。
- `practice` 只有通过 V1/V2/V3 且完成一次最小实践后，才可把知识卡片摘要追加到项目根 `script_patterns.md` 的 Imported 区；未通过项只留在对象级 `analysis.md`。
- `dual` 先分别写对象级 benchmark/practice 证据，再按以上规则各自汇总；账号级信号与单条卡片不合并成一个“万能配方”。

## benchmark：账号级参照

适用于“找对标”“学这个账号”“看几条样本表现如何”这类请求。目标是得到可供 seed / script 参考的定性信号，不是替用户改 rubric。

### 最小工作流

~~~
[读取 state 与已有 study 状态]
  ↓
[筛选公开样本：相关性 / 可达量级 / 内容形态 / 阶段 / 可取得证据]
  ↓
[收集 3–10 个样本：脚本或摘要 + 表现数据 + 用户印象]
  ↓
[逐条记录高 / 中 / 低印象及理由，允许与数据冲突]
  ↓
[只提取有证据的定性模式，标记 Imported, untested]
  ↓
[用户 review → 确认后写 benchmark 与样本归档]
~~~

- 样本少于 3 个时，只保存样本事实与缺口，不输出账号级模式结论；建议收集 3–10 个，不为了凑数虚构样本。
- 每条至少记录来源、标题或内容 ID、可见表现数据（如播放/点赞/评论/转发）和用户印象（高/中/低 + 一句理由）。数据与印象冲突时保留冲突，不替用户裁决。
- 可选地记录脚本、评论和公开的内容形态；没有脚本时可以做浅层参照，但不得假装完成了写法拆解。
- 选择对标时优先采用：领域相关、用户可达量级、内容形态匹配、阶段可学、证据可取得的对象。只分析公开材料。

### benchmark 产出

benchmark.md 记录账号信息、样本表、用户印象、主题/调性分布和定性参照信号。结论必须引用样本证据，并注明“可借鉴但未验证”。

可以写“高表现样本共同出现了具体案例 + 明确冲突”，不能写成“该结构必然带来高表现”。benchmark 的结果是**定性参照**，不能直接改 rubric 权重；任何权重升级仍走 oracle-bump 的全量重打与验证流程。用户自己的实绩成为主信号后，旧 benchmark 保留作 sanity check，不删除。

## practice：单条机制练习

适用于“拆这条稿”“我想学他的表达”“把这个机制练到我的内容里”。一次只练一条材料；账号总结属于 benchmark，不要把两种证据混成一份结论。

### 最小工作流

~~~
[取得一条文稿 / 手动转写 / 公开文本]
  ↓
[AI 起草两句话：讲了什么？为什么有效？]
  ↓  用户复述确认（未确认不继续）
[拆产出与机制：定义 / 因果 / 边界 / 操作 + 具体证据]
  ↓
[用户质疑：哪里不成立？换到自己的赛道会怎样？]
  ↓
[迁移到用户某条轨道，登记一次最小实践]
  ↓
[三重验证门 → 通过才写知识卡片]
~~~

### 复述、质疑、迁移、实践

1. **复述**：用户先用自己的话说“这条在讲什么、为什么值得讲”。AI 可以起草，但最终复述必须由用户确认或改写；不能代答后直接拆解。
2. **拆机制**：至少说明定义、作用机制、适用/不适用边界和下一步动作。引用原文、时间段或结构证据；描述（看到了什么）与推断（为什么可能有效）分开。
3. **质疑**：每条必须找出可质疑处：逻辑漏洞、被省略的前提、换到用户赛道/人设后可能失效的地方。用户反驳也记录为经验，不强行达成共识。
4. **迁移**：把机制改写成用户自己的动作，明确落到某个内容轨道和某个段落；没有轨道落点就不产出卡片。
5. **最小实践**：登记下一条 draft 的一个可观察改动（例如某一段的开场骨架），并写清预期观察、反例和复盘入口；不承诺爆款。

### 三重验证门

每个“值得偷”的机制逐项验证。验证不过仍可留在 analysis.md 的“未通过验证”节，但不进入 techniques/：

| 门 | 必须回答 | 不通过示例 |
|---|---|---|
| **V1 跨域** | 除本条外，另一条该作者/另一位作者/用户真实案例也成立吗？ | 只适用于本题材的一次性技巧 |
| **V2 预测力** | 能否推演一个尚未拆过的场景，并给出具体做法？ | 只会说“看起来很有道理” |
| **V3 独特性** | 抹掉作者名字后，是否仍不是任何创作者都知道的常识？ | “开头要抓人”“要有互动” |

全项通过不是默认结果；如果每项都通过，回查 V3 是否把常识放水进来了。知识卡片至少包括：来源、机制、用户理解/反驳、适用边界、触发场景、反例、用户轨道落点、最小实践与验证状态。

## dual：共享归档、分离结论

适用于用户同时给出账号与多条样本，或明确说“既要看账号规律，也要练这一条”。先建立共享素材归档，再分别跑账号级和单条级证据链：

1. 先按 study/<对象>/samples/<content-id>/ 归档共同素材和公开数据。
2. 先输出 benchmark 的样本、表现数据、用户印象和定性参照；不能把相关性写成因果。
3. 从样本中推荐一个最适合深拆的内容，并说明推荐依据；必须由用户确认深拆样本，不能代替用户决定。
4. 用户确认后才进入 practice 的复述、质疑、迁移、最小实践和 V1/V2/V3 验证。
5. 分别写 benchmark.md 与 techniques/；账号级信号与单条知识卡片互相引用来源，但不合并为一个“可复制配方”。

统计关联只能是待验证假设，不自动成为可复制机制；机制要经过单条证据、跨域验证和用户实践。若用户只需要其中一条交付，退回最轻的 benchmark 或 practice，不启动另一条链。

## 兼容别名与迁移

- 旧命令 oracle-learn-from（账号级导入）和 oracle-apprentice（单条手艺拆解）显示迁移提示后进入本 skill 对应模式；只执行这里的新模式，不回到重复的旧工作流。
- 旧 study 工件可读，作为兼容说明保留；旧入口写入的 benchmark.md、样本目录、analysis 文件读取时标注旧格式和来源。新写入统一使用 study/<对象>/samples/<content-id>/ 及本 skill 的输出位置。
- 迁移不是自动移动：先展示拟读取/拟写入/拟归档的路径、字段和影响，得到用户确认后才写入。没有确认时只读、不改目录、不改 state。
- 旧状态中的 benchmark 字段继续兼容；apprentice 相关字段迁移为 study 记录时，先说明唯一写入者、默认值和是否需要 schema bump，再等待确认。

## 制作层边界

“拆包装”“拆视频动效”“视觉逆向”或旧 --visual 请求不在 oracle-study 内实现。包装/动效请求明确路由给 video-production-workflow，由 VPW 负责证据、规格、制作与 QA；本 skill 只保留文字与机制层学习记录，不写剪辑计划、成片验收或视觉制作中间件。

## Refusals

- 只有一个样本却要求账号级规律：保存事实，说明证据不足，不硬凑 benchmark 结论。
- 要求直接调 rubric 数值权重：拒绝，输出定性信号并指向 oracle-bump。
- 要求跳过用户复述、质疑或验证门直接出“可复制技巧”：拒绝，先完成对应 checkpoint。
- 要求把一条统计相关性宣传成因果或爆款保证：拒绝，改标为待验证假设。
- 要求自动搬迁旧 study 目录或静默改 state：拒绝，先展示影响并等待确认。
- 要求在本 skill 内拆视频包装、动效或剪辑：路由 video-production-workflow，不复制制作实现。

## Integration

- 上游：oracle-init 提供用户档案、content plan、轨道和 state；缺少初始化时先走 /oracle-init。
- 下游：benchmark 的定性参照可供 oracle-seed / oracle-voice 读取；通过验证的 technique 卡片可在下一条 draft 练习并由 oracle-retro 记录结果。
- rubric 权重变化只由 oracle-bump 处理；视觉包装和动效制作只由 video-production-workflow 处理。
