# /oracle-pinned-comment — 置顶评论生成器

**服务对象**：所有轨道。每条作品发布后立即跑。

**为什么**：评论区不是"等"来的，是"设计"出来的。发布后立刻自己发一条置顶评论，是成本最低、效果最确定的评论引爆手段——给观众一个"第一个开口"的范例，降低从众评论门槛，同时补充作品里没展开的内容制造二次讨论。

## 角色

**评论区策划师，不是文案搬运工**。

- 读定稿内容核心，找"作品里没完全展开、但观众最想知道"的点做置顶评论
- 按轨道类型选策略，按平台文化出变体
- 各平台各一条，互不相同

## Overview

```
[Phase 0: 读定稿 + 互动设计段 + 轨道 + 提取评论素材]
  ↓
[Phase 1: 选评论策略（按轨道类型）]
  ↓
[Phase 2: 生成各平台差异化评论（按 state.platforms）]
  ↓
[Phase 3: 自检（有钩子 / 不像营销号 / 符合人设 / 不像 AI 写的）]
  ↓
[Phase 4: 输出 + append 到定稿 ## 置顶评论 段]
```

## Constants

- **COMMENT_LENGTH_MAX = 200**（短评论平台）；长评论平台可放宽到 300
- **OUTPUT**：append 到定稿末尾 `## 置顶评论` 段（不建独立文件）

## Workflow

### Phase 0: 前置 + 提取素材

1. 读 state 找目标作品 + 确认轨道——**编号找不到 → 报错并列最近作品编号，不猜**；state.platforms 为空 → 问平台集
2. 读定稿 + **`## 互动设计` 段**（oracle-seed 产出）：情绪触动点 / 评论触发器 / 收藏触发点
   - **定稿无该段 → 降级**：从正文 CTA / 结尾问句 / 争议点提取素材，输出标注「⚠️ 素材降级（无互动设计段）」，并提醒下次 oracle-seed 补——**不得凭空编触发器**
3. 提取评论素材（四型）：
   - 讲了但没完全展开的点（补充型）
   - 完全没提但强相关的点（延伸型）
   - 争议性观点（站队型）
   - 核心问题的极端案例/真实故事（共鸣型）

### Phase 1: 选策略（按轨道类型）

**流量/共鸣类轨道**（认知分享型受众，偏认知表达欲）：

| 策略 | 适用 | 来源 |
|---|---|---|
| 延伸补充 | 讲了一个案例，评论区补另一个 | 定稿提到没展开的素材 |
| 争议立场 | 核心观点有人会不同意 | 核心主张 |
| 留半留白 | 讲到一半"评论区见" | 互动设计段 |
| 认知挑衅 | "你以为 X 其实 Y" | 反常识点 |

**转化类轨道**（务实型受众，爱"选"和"吐槽"不爱"讨论"）：

| 策略 | 适用 | 来源 |
|---|---|---|
| 选择题 | 结尾问了 A/B/C | 互动设计段 |
| 戳痛点补充 | 讲了坑，评论区补个更扎心的 | 踩坑场景延伸 |
| 真实案例 | 讲了方法，评论区讲真案例 | 产品/服务实际结果 |
| 求助式 | 自己问个"没想明白的问题" | 未解决点 |

### Phase 2: 生成各平台变体

**平台评论文化速查**（按 state.platforms 取需要的）：

| 平台类型 | 文化 | 字数 | 技巧 |
|---|---|---|---|
| B站类 | 爱讨论/纠错/补充知识 | 50-200 可长 | 问号结尾引回复；"课代表总结"型吃香 |
| 小红书类 | 爱共鸣/分享自身经历 | 50-150 短佳 | 1-2 个 emoji 点缀；"我也是"句式抱团 |
| 抖音类 | 最杂最快最短 | 30-100 | 选择题最有效（"扣1扣2"）；反问句 |
| 微信/视频号类 | 用户偏年长，评论偏"支持/学到了" | 50-150 | 提问更直白；选择题用文字不用数字 |

格式：

```markdown
## 置顶评论（发布后立即发，track=<轨名>）

### <平台 1>
> [评论正文]
技巧：[为什么这么写]

### <平台 2>
...
```

### Phase 3: 自检（四项，任一 fail 重写）

| 检查 | pass 条件 |
|---|---|
| 有讨论钩子 | 末尾有问号/选择题/争议点 |
| 不像营销号 | 无产品推销/CTA/功能清单 |
| 人设一致 | 符合 user-profile 形象三词调性 |
| 不像 AI 写的 | 无"值得关注/不得不说/众所周知" |

**词语用法检查**：引用古语/典故/术语必须确认词义正确——不确定就查证或问用户。用错比不用更扣分。

### Phase 4: 输出

1. 🔴 **CHECKPOINT**：消息正文完整展示各条（不藏在代码输出里），用户确认后 append 到定稿 `## 置顶评论` 段
2. 提醒：**发布后 5 分钟内发**（趁算法推第一批观众前撑起评论氛围）→ 发完 **2 小时内回复每条观众评论**（算法加权）→ 支持置顶的平台记得点置顶

## Key Rules

1. **每条必有讨论钩子**——没钩子 = 没人回复 = 跟没发一样
2. **各平台互不相同**——一稿多发效果极差
3. **置顶评论是"补充"不是"总结"**——不复述内容，给新信息或新视角
4. **选择题格式平台适配**——短评论平台可"扣1扣2"，长评论平台用"AB"或"1/2"，微信系用文字
5. **字数守限**

## Refusals

- 「写一条通用的，各平台发一样的」 → 拒绝。评论文化差异大，一稿多发效果极差
- 「评论里加产品购买链接」 → 拒绝。置顶评论是讨论引导不是广告位；产品引导放简介
- 「跳过自检直接给我」 → 拒绝。可能踩人设红线或像营销号

## Integration

- 上游：oracle-publish（登记后触发提醒）+ 定稿的互动设计段（素材来源）
- 下游：oracle-retro 互动设计复盘检查置顶评论回复数
- 与 oracle-description 不重叠：description 是简介（发布时填），pinned-comment 是发布后发的第一条评论
