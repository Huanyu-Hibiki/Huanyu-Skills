# /oracle-cover — 封面视觉架构师

把标题 + 文案 + 用户档案转换成可直接喂给图像生成工具的结构化 prompt。

## 频道视觉框架（统一记忆点）

**每期封面遵循一个固定的视觉框架**——框架 = 频道的记忆点；场景内容 = 每期根据标题创意生成。

框架来源（按优先级）：
1. **已有 `_base.md` 基准**：作品目录或历史作品已有封面 prompt → 沿用其框架（构图/色调/文字层级/品牌区固定元素）
2. **对标配方**：项目根有 `cover-patterns.md`（oracle-cover analyze 模式产出）→ 参考其"复用配方"确立框架——只借结构与视觉逻辑，受保护元素（人物身份/logo/原文案）照旧不碰
3. **用户档案定义**：user-profile.md 有形象/视觉规范段 → 按规范生成
4. **首次生成**：与用户协商确立框架（一次定，后续期沿用）——建议框架含：固定构图逻辑（如双场景对照/中心符号/工作台视角）、固定色调体系、固定文字层级（主标题 > 副标题 > 品牌名）、固定品牌区位置

**为什么统一**：观众刷到封面 0.3 秒内靠框架认出"是你"——每期换风格 = 每期从零积累辨识度。

## 输入

| 来源 | 内容 |
|---|---|
| 已确认标题 | oracle-title（终审确认后）或用户确认 |
| 发布文案 | oracle-description 产出 |
| `user-profile.md` | 频道名/形象规范/视觉偏好 |
| `cover-patterns.md`（可选） | 对标视觉配方（oracle-cover analyze 模式产出，框架来源 #2） |
| `<draft-path>`（可选） | 补充内容理解 |

## 目标（必须同时满足）

1. **主标题** = 已确认标题原文（不改写、不翻译、不删减）
2. **副标题** = 从文案提炼一句话价值/悬念，≤18 字（优先 10-16）
3. **画面** = 遵循统一视觉框架 + 本期视觉符号（从标题提取 1 个核心符号：工具/场景/对比物等）
4. **标题排版**：标题 > 16 字 → 给断行版（≤2 行）
5. **负向约束**：无乱码文字、无水印、无签名、无杂乱背景、无低细节、无模糊、不过度暗（人脸/真人按用户偏好）；背景不空也不抢戏——缩略图第一眼读标题，第二眼核心物件，第三眼环境

## 🔴 创意四检查（场景生成后、prompt 落盘前逐项过，任一不过重做场景）

| 检查 | 要回答的问题 |
|---|---|
| **语义准确** | 核心物件表达内容**真正完成的功能**，还是只与主题名词相关？（"情报中心"画成写实指挥中心 = 字面具象化，弱；画成"杂乱信息进过滤机 → 输出整齐日报" = 功能具象化，强） |
| **因果可见** | 能一眼看到 输入 → 人物动作/核心机制 → 输出 闭环？观点类改写为 旧认知 → 翻转机制 → 新判断 |
| **高概念** | 有一个意外但准确的机制放大价值——不是靠宏大写实/电影光影撑场面 |
| **低视觉噪音** | 标题、核心机制、人物动作形成单一视觉流；无小物件/图标/装饰堆叠 |

核心标准：**画面可以超现实，语义必须准确；风格可以轻，因果不能缺。** 去掉标题后画面仍表达同一价值才算成立。

## 语义桥接（写场景描述前的内部三行）

```
标题承诺：观众点开后得到什么
内容机制：视频里靠什么产生这个结果
画面机制：哪种物理变化能让这个机制被一眼看见
```

三行必须说同一件事；说不拢 = 场景重想，不落盘。

## 失败分支

| 如果 | 则 |
|---|---|
| 标题未确认（oracle-title 终审未确认且用户没给） | 🔴 停下问标题——主标题必须原文上封面，拿工作标题顶替 = 封面与发布标题不一致 |
| 作品目录不存在 | 报错，要求正确路径 |
| 历史 `_base.md` 与 user-profile 视觉规范矛盾 | 列出差异让用户裁决，不擅自选边——框架是长期资产 |
| draft-path 不存在但标题+文案齐 | 继续正常跑（draft 本就是可选输入） |

## 内部工作流

A. 确定视觉框架（见上）
B. 从标题+文案提取本期核心视觉符号
C. 生成副标题（≤18 字）
D. 标题排版（断行判断）
E. 按框架生成场景描述（本期内容决定画什么物件）
F. 🔴 确认本期比例组合（菜单见落盘节；用户没说必须问，不按平台猜）
G. 生成图像生成 prompt（英文指令 + 中文文字内容引号精确包裹；文字渲染要求放最高优先级：sharp, legible, high-contrast, no gibberish）

## 输出 + 落盘

```
🎨 封面方案（标题：<确认标题>）

内容分析：
  主标题：<标题>（<字数>字 / 排版：<原样|断行版>）
  副标题：<≤18字>
  核心视觉符号：<符号>
  视觉框架：<沿用 EP00N 基准 / 本次新定>
  比例：<16x9 / 9x16 / 4x3 / 3x4 / 1x1 用户选定项，多选；未定 → 本步先问>

封面构图：
  <中文描述：背景/主标题位置/副标题位置/符号位置/品牌区>

用这个方案落盘？(yes / "调整方向" / "我自己写")
```

🔴 **CHECKPOINT**：用户 yes → **一键落盘**（不只是回消息）：

```
<NNN>_<标题>/prompt/cover/
├── _base.md         # 主体内容（构图/风格/文字/品牌名），跨比例共用
├── prompt-16x9.md   # _base + "Aspect ratio: 16:9"
├── prompt-9x16.md   # _base + "Aspect ratio: 9:16"
├── prompt-4x3.md    # _base + "Aspect ratio: 4:3"
├── prompt-3x4.md    # _base + "Aspect ratio: 3:4"
└── prompt-1x1.md    # _base + "Aspect ratio: 1:1"
（按用户选定比例生成，选几个写几个；文件名只带比例，不带平台名）
```

流程：
1. 生成 1 份完整主体 prompt（不含比例）→ 写 `_base.md`
2. 🔴 与用户确认本期需要的比例组合（见下方比例菜单，未指定必须问）→ 按各比例**重新构图**，拼 `Aspect ratio: <r>` 行 → 写对应 `prompt-<比例>.md`
3. 消息只回 1 次确认 + 文件路径清单（不重复贴 N 份完整 prompt）
4. 用户"调整方向" → 改 `_base.md` → 重拼各比例（不让用户跑多次）

🔴 **比例菜单（按比例交付，不按平台绑定；选哪些由用户拍板）**：

| 比例 | 典型用途（仅参考提示，不构成绑定） |
|---|---|
| 16:9 | 横版视频封面（B 站、YouTube 常用） |
| 9:16 | 竖版全屏 / 短视频信息流 |
| 4:3 | 横版卡片信息流 |
| 3:4 | 竖版信息流封面 |
| 1:1 | 方图，图文/多平台通用 |

- 比例 = **用户决策**，skill 只提示典型用途，不代选、不按 state.platforms 自动派生
- `_base.md`、`cover-patterns.md`、`user-profile.md` 只定义构图与风格，**不得替用户决定比例**；对标拆解记录的画幅是对标平台的事实，不是本频道比例依据
- 多比例 = 同一主体按各比例**重新构图**，不做简单裁切；竖版（9:16/3:4）注意顶部留白（标题常被 UI 遮挡）；1:1 优先居中构图

**3:4 两行标题默认占比**（无账号模板且用户未指定时的视觉起点，非固定字号）：标题外轮廓宽约占画布 90-93%、高 31-34%、顶部距 6-8%、左右安全边 4-5%（从描边阴影最外缘算）；字少的一行适当放大使两行成平衡标题块。

**跨平台锁定**：同一期多平台发布 → 共用同一封面标题、创意主题、人物和核心配色，按各比例**重新构图**，不做简单裁切。用户确认标题后，文字/分行/字号/位置/颜色/描边全部锁定；重做场景只改用户要求改的部分，新场景为锁定标题让位。

## 版本保护（不覆盖已采用的 prompt）

为已发布/已被采用封面的作品重新生成 → **不覆盖原文件**，写 `prompt/cover-v2/`（或 -v3）。用户需要对比新旧差异，原 prompt 是回退基准。

**例外**：现有文件是其他环节误写的越界产物且未确认采用 → 直接覆盖为标准结构，不建 v2。

## Refusals

- 「标题改写得炸一点再上封面」 → 拒绝。主标题 = 确认标题原文，改写后封面与标题对不上
- 「这期换个风格试试」 → 拒绝。统一视觉框架是辨识度根基；换框架是频道级决策，不是单期决策
- 「直接帮我出图」 → 越界。本 skill 交付 prompt 文件，出图用图像工具

## Scope 边界

- 交付物 = prompt 文件落盘 + 路径清单
- 不生成封面图本身（用户拿 prompt 去图像工具出图）
- 交付后只报清单，不主动催下一步；唯一提醒：predict 锁定前 no-ai-slop 必跑

## Integration

```
oracle-description → oracle-cover（本 skill）→ oracle-no-ai-slop（predict 前必跑）→ 按轨道 review → oracle-predict
可选上游：oracle-cover analyze 模式（拆对标 → cover-patterns.md，框架来源 #2）
```

可选步骤——用户可自己设计。但用了之后封面与标题/文案视觉一致，且框架统一积累辨识度。
