# Scoring Procedure（打分规程 · 单一来源）

> **被 oracle-score / oracle-predict / oracle-trends 消费**。凡"按 rubric 给维度分、算 composite"的动作，解析与打分纪律都住本文件——改打分口径只改这里（权重变更本身必须走 /oracle-bump，原则 #2），三个消费方自动跟进。
>
> 本文件只定**规程**，不复制任何具体权重/公式——公式永远现场解析自 rubric 该轨节。

## 1. Rubric 解析（三步，异常不猜）

1. 读 `rubric_notes.md` **该轨节**（交叉题两轨各解析一份）
2. 该轨节不存在（cold-start 第 1 篇）→ 从对应 starter（`starter-rubrics/opinion-video-zero.md` / `conversion-video.md` 等，相对 oracle-bone 包根）读 v0 等权公式，**不写文件、不阻塞**，控制台加 ⚠️ 提示
3. 格式与预期不符（用户手改过结构）→ 询问用户当前公式是哪一行，**不自己猜**

解析产物：`rubric_version` / 维度列表与权重 / 归一化常数 / 每维 0-5 含义。

## 2. 逐维打分纪律（所有消费方通用）

- 每维给 **0-5 整数**（不允许 4.5；犹豫 → 选低值 + 备注）
- 一行理由 **≤30 字**，必须引用稿子/素材的具体词或场景——理由是 retro 的诊断工具，不是装饰
- 对照锚点：有 0/3/5 锚点样本时按锚点定义对齐；没有就按该维 0-5 含义打

**score / predict 专属（稿子级打分）**：

- **盲打优先**——先打分再对比锚点实绩，避免被锚定
- **打分速度纪律**——每维 ≤30 秒，超过就是在合理化；**相信第一个整数**

## 3. composite 计算

按该轨节解析出的公式与归一化常数加权折算，**不在本文件复制任何具体公式**。输出必须带公式行（如 `(ER×1.5 + ... ) / 8.5 × 2.0`）让用户可验算。

## 4. 各消费方差异（细则在各 skill，此处只列分界）

| 消费方 | 精度定位 | 专属规则 |
|---|---|---|
| oracle-score | 正式单稿打分 | 只看不落盘；同稿连打 ≥3 次提示决策疲劳；不给 bucket |
| oracle-predict | 预测用精打分 | 打分在内存做，进 7 组件预测；bucket/锚点/反事实走 predict Phase 3+ |
| oracle-trends | **粗打分** | snapshot-based 标注 `rough`；≠ 正式预测——预测必须基于最终稿重打 |
