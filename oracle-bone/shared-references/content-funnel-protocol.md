# Content Funnel Protocol（内容漏斗采访协议）

被 `oracle-init`（Phase 3/4）、`oracle-seed`（轨道分流）、`oracle-recommend`（占比过滤）、`oracle-compass-retro`（规划修订）引用。

本协议规定：初始化时如何通过采访产出**内容规划**（单一/双轨/三轨），以及规划如何注册进 state、被下游消费、被修订。

理论依据：`references/content-funnel-theory.md`（内容漏斗三层模型）+ `references/xu-zuohao-positioning-distill.md` §6（采访问卷）。

---

## 核心理论速览（30 秒版）

内容按漏斗分层，每层服务不同人群、不同目标：

| 漏斗层 | 人群 | 内容 | 成功指标 |
|---|---|---|---|
| **顶层·破圈** | 最广受众（含"只是爱看"的人） | 吸引更广泛目标用户的普适内容 | 播放 / 涨粉 / 破圈转发 |
| **中间层·认知** | 目标用户（潜在会付钱） | 专业积累 / 行业洞察 / 方法论 | 同频评论 / 收藏 / 信任建立 |
| **底层·转化** | 购买意向用户 | 产品 / 服务 / 案例展示 | 咨询 / 私信 / 付费 |

三条铁律：
1. **流量 ≠ 客户**——1000 播放带来 1-2 个高意向咨询，比 10 万泛流量更有价值（对转化层）
2. **破小圈不破大圈**——破圈内容也要破进"目标用户聚集的相邻圈"，不是破进完全无关的大众
3. **漏斗各层底层逻辑必须统一**——价值观/审美/人设一致，否则破圈来的人接不住，转化层的人被吓跑

## 采访流程（init Phase 3，5 问）

AI 逐问采访，用户回答后 AI 复述确认（协作契约 #6），全部完成后产出 content-plan.md。

### 问题 1：三类人群盘点

> 你的内容给谁看？请分三类说：**会付钱的** / **潜在会付钱的** / **只是爱看的**。

- 依据：商业模式反推画像（付费者优先）
- AI 辅助：结合 Phase 2 用户档案（变现方式/客单价/典型客户）提示"付钱给你的人是谁"

### 问题 2：逐层能力提问

> 对照三层漏斗逐层看：
> - **破圈层**——你能做吗？想占多少？（吸引更广泛目标用户的内容）
> - **认知层**——你的专业优势支撑哪类？（分享积累/洞察/方法论）
> - **转化层**——你的变现落点是什么？（产品/服务/案例）

- 某层用户明确做不了 / 不想做 → 该层剔除
- 依据：用户 Phase 2 档案的专业优势 ↔ 漏斗层匹配

### 问题 3：占比拍板

> 各层占比你定（AI 只给参照：双轨常见 40/60，三轨常见 4:3:3，单一轨 100%）。

- **AI 不代定占比**——只给参照系 + 当前精力评估，用户拍板
- 占比写入 state 的 `tracks.definitions[].mix_ratio`，之和必须 = 1.0

### 问题 4：各层成功定义

> 每层"成功"长什么样？（破圈层看播放/涨粉，转化层看咨询/付费——不能用同一把秤）

- 每轨产出 2-3 条可观测指标，写入 `success_metrics`
- 反面校验：问"什么信号出现你就知道这轨做成了/做砸了？"

### 问题 5：漏斗外劝退测试

> 有没有你绝对不碰的内容？（不相干热点 / 个人生活边界 / 竞品话题 / 议题红线）

- 产出"漏斗外排除项"清单，写入 content-plan.md
- 后续 oracle-trends / oracle-recommend 遇命中排除项的候选自动降级或标注

## 规划判定（三选一）

| 规划 | 结构 | 适用 | 判定信号 |
|---|---|---|---|
| **单一内容** | 1 轨（聚焦一层） | 纯品牌/纯转化起步，或精力只够一条线 | 问题 2 只有一层做得了 / 用户明确"先聚焦" |
| **双轨内容** | 2 轨（破圈 + 转化） | 最常见配置 | 有专业优势能破圈 + 有明确变现落点 |
| **三轨内容** | 3 轨（破圈 + 认知 + 转化） | 完整漏斗，品牌/流量/转化全要 | 三层都有能力且精力允许 |

判定规则：**按用户在问题 2 的回答决定有哪些层，不硬凑**。做不了认知层的用户走双轨；只想做转化的走单一。AI 可以提示"双轨是最常见起步配置"，但不代选。

## 轨道注册（state 格式）

每轨四要素注册进 `state.tracks.definitions`：

```jsonc
{
  "id": "convert",                    // 机器引用 id（用户命名转 slug）
  "funnel_layer": "转化",              // 破圈 | 认知 | 转化 | null（单一轨时）
  "name": "获客案例轨",                // 用户命名
  "rubric_section": "rubric_notes.md#track-convert",
  "rubric_version": "v0",
  "review_skill": "oracle-open-source",   // 转化轨 → open-source；破圈/认知轨 → oracle-who-for
  "success_metrics": ["咨询数", "私信转化"],  // 问题 4 产出
  "retro_windows_days": [3, 7, 30],       // 转化轨多窗口；流量轨默认 [3]
  "mix_ratio": 0.6                        // 问题 3 拍板
}
```

**review skill 路由规则**：
- 转化类轨道（funnel_layer=转化）→ `oracle-open-source`（审查推理过程呈现 + 降低决策风险），加载 `references/conversion-track-playbook.md`
- 破圈 / 认知类轨道 → `oracle-who-for`（受众价值采访，以 init 画像为基线）

**rubric starter 路由**：
- 破圈/认知类轨道 → `starter-rubrics/opinion-video.md`（cold-start 用 zero 版）
- 转化类轨道 → `starter-rubrics/conversion-video.md`

## 画像推导（init Phase 4 衔接）

按 content-plan 每轨推导画像 → `audience-profiles.md`。每轨画像五要素：

1. **人群定义**（是谁 / 怎么刷到 / 为什么停留）
2. **痛点与需求**（他们在找什么）
3. **互动特征**（会怎么评论 / 什么话术触发咨询）
4. **转化路径**（从看到内容到信任到行动）
5. **一般关注画像**（非目标但会刷到的人：会怎么评价 / 会不会转发 / 可能质疑什么）

> oracle-simulate-audience 的两类人群模拟（核心受众/一般关注）**直接以这份画像为根基**。oracle-who-for 是逐稿深化层（基线画像 → 逐稿 brief 关系）。

付费者优先纪律（画像三法之一）：画像从"谁付钱"反推，不从"谁点赞"正推——点赞的人不一定是客户。

## 下游消费表

| skill | 怎么消费规划 |
|---|---|
| oracle-seed | 分流时按候选 track 落轨；用户没明说 → 按 mix_ratio 补稀轨 |
| oracle-recommend | 按占比过滤推荐（哪轨最近发少了补哪轨）；交叉题 0.5+0.5 |
| oracle-score / oracle-predict | 按该轨 rubric 节打分；prediction header 写 Track |
| oracle-retro | 按该轨 retro_windows_days 分窗口回收；按该轨 success_metrics 对账 |
| oracle-bump | 按轨独立重打校准池 |
| oracle-status | 分轨显示样本数 / 收敛度 / buffer |
| oracle-compass-retro | 每 2 期诊断各轨健康度 → 产出规划修订**候选**（不改 plan） |

---

## 规划修订机制

规划不是一次定终身。修订走这条链：

```
跑满若干期 → oracle-compass-retro 诊断各轨表现
  → 产出修订建议（如"转化轨样本足够但破圈轨一直拖，建议占比 4:6 → 3:7"）
  → 用户拍板（AI 不代改 plan）
  → 同步 state.tracks（definitions + mix_ratio + mix_ratio_note 追加修订记录）
  → content-plan.md 同步更新
```

修订触发参考：
- 某轨连续 3 期指标垫底 → 建议降占比或删轨
- 某轨咨询/转化爆发 → 建议升占比
- 用户变现模式变化（新增产品线）→ 建议增轨

---

## Refusals

- 「一轨 rubric 打所有轨道」 → 拒绝。破圈轨和转化轨的成功指标不同，共用 rubric 会让校准信号互相污染
- 「占比你来定就行」 → 拒绝代定。AI 给参照系，占比是用户战略决策
- 「先不规划轨道，直接开始做」 → 提示：无轨道规划时候选池/打分/复盘全部退化为混池校准，信号稀释。至少先定单一轨
- 「转化轨也用 who-for 审查」 → 拒绝错配。转化轨走 open-source（审查的是"降低决策风险"，不是"受众同频"）——拿不准时回 state 查 review_skill 字段
