# WORKFLOW — oracle-bone 工作流速查

## 每期完整链路（顺序敏感）

```
oracle-seed（按轨分流写 draft，含互动设计段）
  ↓
oracle-title（3-5 候选）→ oracle-title-pick（淘汰制选优 + 三处改名同步）
  ↓
oracle-description（各平台文案 append 到定稿末尾）→ oracle-cover（_base + 平台比例派生）
  ↓
oracle-no-ai-slop（AI 味检测与修正 —— 预测前必跑，绝不跳过）
  ↓
按轨道 review：
  流量/共鸣轨 → oracle-who-for（以 init 画像为基线逐稿深化）
  转化轨     → oracle-open-source（9 问 + 反套路镜子）
  ↓
[可选] oracle-simulate-audience（评论区预演）/ oracle-compliance（合规扫描，任意轮可复检）
  ↓
oracle-predict v1（盲预测，预测段锁定）
  ↓
实际制作（AI 不可见）
  ↓
oracle-shoot（登记 + buffer+1；定稿 diff ≥30% → predict v2）
  ↓
实际发布
  ↓
oracle-publish（合规 gate → 登记 URL + buffer-1）
  ↓
oracle-pinned-comment（发布后 5 分钟内）→ oracle-derivative（T+1 衍生）
  ↓
oracle-retro（窗口按轨道：流量轨 [3d] / 转化轨 [3,7,30]）
  └─ 每 2 期 → oracle-compass-retro（账号诊断 + 规划修订候选）
  ↓
oracle-bump --track <id>（该轨样本够 + 信号强时升级 rubric）→ 回到 seed
```

## 主链路铁律

predict → （制作）→ shoot → （发布）→ publish → retro。
publish 严格只用于"已实际发到平台且有真实 URL"。**没有真实 URL 就不是 publish。**

## 三条不可妥协原则

1. 盲预测——预测段写完即 immutable（hook 强制）
2. 升级 = 全量重打——排序一致性 ≥0.8 + 跨模型审
3. rubric 是工作台不是博物馆——被推翻/被吸收的观察删掉
