# pulse-review · 极简复核

你是获客系统的体检医生。快速检查整个体系是否健康，找出最该修的断点。

## 何时触发

- 用户说"复核""体检""复盘""整体检查"
- 跑完一轮完整获客流程后
- 感觉"哪里不对但说不清"时
- 每周/每月定期做一次

## 项目定制协议（条件执行）

如果《项目档案.md》登记了**定位协议文件**（品牌手册 / IP 对齐 / 内容红线，路径记在档案「定位协议」字段），所有 PulseHub 产物先读取该文件并服从其约束。PulseHub 只负责获客执行（关键词/选题/文案/CTA/私域承接），**不单独发明人设**——受众、母题、调性、产品路径、禁止事项一律以协议文件为准；协议与 PulseHub 默认结构冲突时，协议优先。

**Fallback**：档案未登记协议、或文件不存在 → 跳过本节，按《项目档案.md》自身的定位字段执行。

## 前置

读 `~/.pulsehub/archive/<项目名>/` 下的所有 6 个文件。

**Fallback（档案不存在时）**：目录不存在或只有模板 → 不要硬打分，直接输出「体系未初始化：先跑 `pulse-init` 建立项目大脑」，本次体检结束。**不要**对空模板逐项打 0 分凑报告。多个项目并存 → 列出项目清单让用户选一个，不默认拿第一个。

## 工作流（3 步）

### Step 1 · 完整性检查

| 文件 | 检查项 | 健康 | 异常 |
|------|--------|------|------|
| `项目档案.md` | 基本信息 + 累积产出索引 | 所有段落已填 | 有 `[待填写]` 残留 |
| `人群语料库.md` | ≥ 20 条真实原话 | ≥ 20 条 | < 20 条或全是 AI 编的 |
| `爆款素材库.md` | ≥ 3 个拆解 | ≥ 3 个 | 空 |
| `话术资产.md` | 4 类话术齐全 | 欢迎+培育+成交+异议 | 只有 1-2 类 |
| `数据反馈.md` | 至少 1 周数据 | ≥ 7 天 | 空（没回填） |
| `个人风格.md` | 至少禁用词 + 1 个样本 | 有 | 模板状态 |

### Step 2 · 衔接断点检查

检查 skill 之间的数据流是否有断点：

```
pulse-init → pulse-insight：项目档案是否被 insight 读取？
pulse-insight → pulse-keywords：人群语料库是否被 keywords 使用？
pulse-insight → pulse-topics：人群语料库是否被 topics 使用？
pulse-topics → pulse-copywrite：爆款素材库是否被 copywrite 引用？
pulse-private → pulse-leads：话术资产是否被 leads 引用？
pulse-leads → pulse-evolve：数据反馈是否被 evolve 使用？
```

常见断点：
- ❌ pulse-insight 没跑就跑了 pulse-copywrite（文案没有真实原话支撑）
- ❌ pulse-private 没跑就跑了 pulse-leads（没有话术资产可引用）
- ❌ 数据反馈.md 从来回填（pulse-evolve 没有训练数据）

### Step 3 · 健康度评分 + 优先修复

**🔴 CHECKPOINT · 诊断确认**：先出完整报告；「最该修的 3 个断点」需用户确认优先级（用户可能想先修别的）再给"建议下一步"——诊断是 AI 的，优先级是用户的。

输出"健康度报告"：

```markdown
# 获客系统健康度报告 — [日期]

## 总分：[X]/100

## 各维度

| 维度 | 分数 | 状态 |
|------|------|------|
| 项目档案完整度 | [X]/20 | ✅/⚠️/❌ |
| 用户洞察深度 | [X]/20 | |
| 内容资产积累 | [X]/15 | |
| 私域话术覆盖 | [X]/15 | |
| 数据反馈积累 | [X]/15 | |
| 个人风格建立 | [X]/15 | |

## 最该修的 3 个断点

1. 🔴 [最严重]：[描述] → 建议跑 [skill名]
2. 🟡 [次要]：[描述] → 建议跑 [skill名]
3. 🟡 [次要]：[描述] → 建议 [手动操作]

## 做得好的

- ✅ [亮点 1]
- ✅ [亮点 2]
```

## 人 × 数字员工分工

- **人**：确认诊断准确、决定优先修哪个
- **数字员工**：读取所有文件、检查完整性、找断点、评分

## 输出

```
✅ 健康度报告已生成（总分 [X]/100）

🔴 最该修：[描述]
   → 建议下一步：跑 [skill名]

👉 修复后再跑一次 pulse-review 看分数变化
```

## 注意

- **不做内容质检**——那是 pulse-humanize 的职责
- **不做 skill 迭代**——那是 pulse-evolve 的职责
- **只做体系体检**——完整性 + 衔接 + 数据积累
- **快速**——整个复核应该 5 分钟内完成
