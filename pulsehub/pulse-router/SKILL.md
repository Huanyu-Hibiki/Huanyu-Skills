# pulse-router · 决策路由

> **位置**：PulseHub 获客系统**第 0 步**。在 `pulse-init` 之前。
> **角色**：**路由器**，不是执行器。本 skill 不产出内容，只判断下一步调什么。
> **类比**：前台分诊——根据症状判断你该挂哪个科。

## 何时触发

- 用户说"开始做获客""我想找客户""怎么做新媒体获客"——但还没填过项目档案
- 用户描述了自己的生意，但说不清"是什么 / 给谁 / 怎么收费"
- 用户带着方案来问"这个选题对不对""这个策略够不够"
- 用户跑完整个获客流程后想**复盘整体策略**

**不进 router 的场景**：
- 用户已经跑过 `pulse-init`，有项目档案了——直接进对应业务 skill
- 用户只想解析一个 URL——直接调 `pulse-resolve`
- 用户只想找热门帖子——直接调 `pulse-discover`

## 工作流（3 步）

### Step 1 · 诊断清晰度（4 题，心中判断，不直接问用户）

| # | 判断点 | 清晰 | 模糊 |
|---|--------|------|------|
| 1 | **是什么**：产品能用 1 句话说清吗？ | ✅ | ❌ |
| 2 | **给谁**：能说出具体画像（角色 + 场景 + 痛点）？ | ✅ | ❌ |
| 3 | **怎么收费**：有客单价 / 计费方式 / 变现路径？ | ✅ | ❌ |
| 4 | **MVP**：能说出"这个周末能 ship 的最小版本"？ | ✅ | ❌ |

**路由规则**：

| 清晰度 | 判断 | 路由到 |
|--------|------|--------|
| 4/4 ✅ | 方向清晰 | → `pulse-init`（正式初始化） |
| 3/4 | 略模糊（差 1 项） | → `pulse-init`，但在 init 过程中重点补这一项 |
| ≤ 2/4 | 方向模糊 | → 先引导用户想清楚（见 Step 2），**不急着进 init** |

**🔴 CHECKPOINT · 🛑 方向模糊时停住**：≤ 2/4 时**不进 init**——即使你说"直接开始吧"，也要先在 Step 2 把缺的项补到 ≥ 3/4。这是硬门槛，不是建议。

### Step 2 · 模糊时怎么引导（不替代用户思考）

如果 ≤ 2/4，**不要替用户做决定**。**所有 forcing question 必须以 ABCD 选项抛出（OP 用户硬偏好，2026-07-28 实证）** —— 每项一句话说明，允许多选 + 自补，不要追加"或自定义答案"尾巴。

| 差哪项 | ABCD 选项 |
|--------|-------------------|
| "是什么"模糊 | A. 给 12 岁孩子讲 / B. 给同行讲 / C. 给潜在客户讲 / D. 给我自己讲 |
| "给谁"模糊 | A. 画具体人物画像 / B. 举出上一个付费客户 / C. 列出 3 个候选人 / D. 都不清 |
| "怎么收费"模糊 | A. 已设客单价 / B. 按效果 / C. 按工作量 / D. 还没想 |
| "MVP"模糊 | A. 周末能 ship / B. 一个月能 ship / C. 三个月能 ship / D. 现在连脚本都没 |

**原则**：抛完选项让用户挑，**不要接着给建议**。用户想清楚后再进 Step 3。

### Step 3 · 路由到下一步

| 用户状态 | 推荐下一步 |
|---------|-----------|
| 方向清晰（4/4），首次启动 | → `pulse-init`（创建项目档案 + 建立 project-archive） |
| 方向清晰，已有档案 | → 按需求路由（见下表） |
| 想找评论机会 | → `pulse-discover` + `pulse-leads` |
| 想写文案 | → `pulse-copywrite`（需先有 `人群语料库.md`） |
| 想做选题 | → `pulse-topics` |
| 想复盘整体 | → `pulse-review` |
| 方向还模糊 | 停在 Step 2，继续引导（**不进 init**） |

## 与 pulse-init 的边界

- `pulse-router`：**判断**该不该开始 + 该走哪条路
- `pulse-init`：**执行**初始化（填档案、建大脑）——它的"前期决策校验 6 步"是**已有方向后**的进一步校验，不替代 router 的诊断

router 是"你还不能上车，先去买票"；init 是"买好票了，上车系好安全带"。

## 调用示例

```
用户："我想做新媒体获客，我是做英语培训的"
router 判断：
  1. 是什么：英语培训 ✅
  2. 给谁：？没说清（少儿？成人？考研？雅思？）❌
  3. 怎么收费：？没说 ❌
  4. MVP：？没说 ❌
  → 2/4，模糊
router 回复："英语培训范围很大。你上一个付费学生更接近哪种？
              A. 少儿兴趣启蒙 / B. 中高考提分 / C. 成人职场口语 / D. 雅思托福留学
              （可多选，也可以直接补充）"
用户回答后，重新判断清晰度。
```

```
用户："我是做造价咨询的，帮建筑工程做投标报价，
       客单价 5000-20000，已有 3 个付费客户"
router 判断：4/4 ✅
router 回复："方向很清晰。建议下一步运行 pulse-init，
             我会帮你建立完整的项目档案。说『初始化』就开始。"
```

## 注意（不要做）

- **不产出任何内容**——router 只做路由
- **不跳过 init**——即使用户说"别废话直接开始"，也要至少跑 pulse-init 的轻量版
- **尊重用户的"还没想好"**——不逼迫用户立刻想清楚，允许"先想想"
- **用户拒答 ABCD** → 允许"先想想"，router 结束本轮；用户带模糊方向强闯 → 放行 init 但在路由结论里写明「缺 X 项，init 的决策校验需重点补」，不静默放行
- **不在 router 里做 init 的活**——用户开始报档案字段（平台/账号/客单价）→ 立即转交 `pulse-init` 接手收集，router 不代收

## 下一步

路由完成后，用户进入对应的 skill。最常见的下一步是 `pulse-init`。

## Pitfalls

### P1. 跳过 router 直接进 init = 跑前没分诊

**症状**：用户说"开始做获客"就直接调 pulse-init，跳过清晰度判断。等到 init 跑到 Step 1-6 才暴露"方向还没想清楚"，浪费用户 6 步决策时间。

**正解**：每次用户表达"想做获客"时，**先按 Step 1 表做 4 题内心判断**，4/4 清晰才进 init；≤3/4 先 Step 2 引导。**不要**默认"用户既然来了就清楚"，事实上大部分 OPC 一人公司主理人对自己方向只有模糊感觉。

**反例**（2026-07-28）：用户说"做获客"→ AI 直接进 pulse-init 跑 Step 1 5 题 → 浪费决策时间。正确做法是 router 先 4 题判断：产品/人群/收费/MVP 都答得清 = 4/4 → 进 init。

### P2. router Step 2 forcing question 用开放式问句（OP 用户硬偏好，2026-07-28 实证）

**症状**：router 抛出"你上一个付费学生是什么样的？为什么选你而不是新东方？"这种开放式长问句。用户花时间组织措辞，决策信息密度低。

**正解**：Step 2 的 forcing question 必须以 ABCD 选项抛出（每项一句话），让用户挑或自补。本 skill "Step 2 模糊时怎么引导"已加 ABCD 选项。
