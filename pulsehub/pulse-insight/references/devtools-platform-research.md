# Chrome DevTools 平台调研规则（PulseHub）

用于 pulse-insight / pulse-keywords / pulse-topics 在需要真实用户语言、关键词热度、选题信号时。

## 核心纪律

1. 不要停在 Bing/搜索引擎结果页。
   - 搜索引擎只能当入口，不算完成调研。
   - 必须进入目标平台或目标平台搜索页：知乎、小红书、抖音/B站、贴吧/论坛、行业站点等。

2. 不要只“新建页面”。
   - 打开页面后必须读取 DOM / snapshot / 可见正文，提取标题、摘要、问题、评论、相关搜索、互动数等。
   - 只创建 tab、没有抽取内容，不算完成。

3. 真实原话分级记录。
   - 详情页/评论区原文：`[平台-详情页/评论]`
   - 搜索页可见标题：`[平台搜索页-笔记标题/问题标题]`
   - 搜索页摘要/AI 摘要：`[平台搜索页-摘要]`
   - 法院/官方/权威文章：`[来源页面-机构名]`
   - AI 推断只能放在“洞察归纳”，不能写成用户原话。

4. 平台受阻要写清楚。
   - 小红书详情页 404/暂不可浏览、贴吧数据获取失败、论坛搜索失效等，要记录为“可用程度低/待补”，不要伪造详情内容。
   - 可用搜索页标题/相关搜索仍可作为弱信号，但要标来源层级。

5. 产出必须落到资产。
   - pulse-insight：写入 `人群语料库.md` 和/或 `付费用户洞察报告.md`。
   - pulse-keywords：写入 `关键词矩阵.md`，并把主战场词同步到 `项目档案.md` 内容策略。
   - pulse-topics：写入 `选题库.md`，必要时更新 `爆款素材库.md`。

## 最低完成标准

- 至少覆盖 2 个目标平台（如知乎 + 小红书），除非平台确实不可访问。
- 每个平台至少提取 5 条可见信号（标题、摘要、相关搜索、评论等）。
- 明确区分：强信号 / 中信号 / 低可用 / 待补。
- 最后验证文件已写入并更新项目索引。
