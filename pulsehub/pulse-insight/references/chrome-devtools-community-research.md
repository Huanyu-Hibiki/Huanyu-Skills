# Chrome DevTools 社区调研流程（pulse-insight）

来源：2026-07-28 `焕羽格致社-工程合规AI获客` 的 pulse-insight 调研，用户纠正“不能只建 Bing 搜索页或看通用文章”。

## 适用场景

当用户要求“用 Chrome DevTools 搜索信息完善用户洞察 / pulse-insight / 用户画像”时使用。

## 核心纪律

1. **不要停在搜索引擎页**：Bing/Google 只能做入口，不能替代社群调研。
2. **直接进目标社区**：知乎、小红书、抖音、贴吧、行业论坛等，要打开站内搜索页或具体详情页。
3. **提取页面可见文本**：问题标题、笔记标题、回答摘要、评论片段、作者/日期/互动数、相关搜索词。
4. **详情页能进就进**：只看列表页不够；若详情页 404/风控/数据失败，要记录“详情不可得”，不要用二手文章补成“真实原话”。
5. **真实原文与洞察分开**：`人群语料库.md` 先存来源标记 + 原文片段；推断只放痛点聚类/洞察报告，不能冒充用户原话。

## 推荐提取维度

| 维度 | 示例 |
|---|---|
| 情绪词 | “天塌了”“绝望”“闯大祸”“无力感” |
| 求助标题 | “第一次做标书废标怎么办？” |
| 具体事故 | 日期写错、签章漏盖、授权书失效、文件属性残留、响应项漏项 |
| 相关搜索 | 平台“大家都在搜”或知乎相关搜索 |
| 平台可用性 | 详情页是否能进、评论是否可读、是否登录/风控 |
