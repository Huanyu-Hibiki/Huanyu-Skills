# Chrome DevTools 关键词验证参考

来源：2026-07-28 PulseHub「工程合规 AI 获客」关键词矩阵会话。

## 核心教训

用户明确要求用 Chrome DevTools 时，不要只开 Bing 搜索页，也不要只创建新页面就结束。关键词验证要进入目标平台站内搜索页，读取页面可见信号。

## 推荐流程

1. 读 `项目档案.md` 与 `人群语料库.md`，先从真实搜索行为中抽候选词。
2. 对 3-5 个候选主词做平台验证：
   - 小红书：`https://www.xiaohongshu.com/search_result?keyword=<encoded>`
   - 知乎：`https://www.zhihu.com/search?type=content&q=<encoded>`
   - 论坛/贴吧：优先站内搜索，不只看搜索引擎摘要。
3. 用 DevTools 读取 `document.body.innerText`，提取：
   - 笔记/问题/帖子标题
   - 作者、日期、互动数（如页面可见）
   - 相关搜索 / 大家都在搜
   - 回答摘要 / 评论片段
   - 失败状态（404、403、数据获取失败、页面不见了）
4. 判断“强/很强”前至少保留 3 条页面可见证据。
5. 落盘时明确区分：
   - 平台可见原文/标题
   - AI 的洞察归纳
   - 不可访问页面边界

## 已验证信号示例

### 小红书：`标书废标原因`

页面可见：
- “90% 废标，都栽在这 10 个小细节上”
- “100个的废标点整理，看完直接避坑”
- “吐血整理！标书废标25项原因，别再掉坑”
- 相关搜索含“做标书废标了怎么办”“投标怎么避免废标”

### 小红书：`标书防废标自查清单`

页面可见：
- “标书自检清单（115条）”
- “投标文件防废标自查清单”
- “标书废标风险自查清单（防废标终极指南）”
- 相关搜索含“电子标书废标自查”“标书废标项清单”

### 知乎：`标书废标原因`

页面可见摘要：
- “80%以上的废标并非因为技术方案不行或报价不合理，而是栽在了细节和规则上”
- 废标原因结构包括资格文件、星号条款、报价细节、签字盖章、密封、文件转换等。

## 关键词矩阵判断原则

- 小账号优先精准词，不硬拼大词。
- 平台验证强 + 情绪强 + 可做清单引流 = 主战场。
- 对本次工程合规 AI 项目，第一轮主战场应优先 `文衡 + 防废标`，再用 `照胆 + AI 审合同靠不靠谱` 承接合同线。
