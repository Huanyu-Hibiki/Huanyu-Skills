# Motion Brief Standards（动效导演简报标准）

> 适用范围：分镜阶段（`video-plan`）对 Remotion / HyperFrames / B-roll 动画设计条目的**规划**，以及 `b-roll-generate` 写实现计划前的**导演简报**。真实素材、Stock、AI 图/视频条目不走本标准。

原则：**先动后效、先逻辑后装饰**。每条动效先用一句话说清"这条动画到底表达什么"，再谈技术实现。规划阶段不写生产代码、不渲染媒体；简报确认后才执行。

## 1. 输入分类（决定规划方式）

分镜规划动效条目前，先判断输入属于哪一类：

| 分类 | 何时使用 | 规划要点 |
|---|---|---|
| **目标帧重构** | 静态标题图、海报、UI 截图、信息卡要"动起来" | 原图即终帧；识别需要拆层的元素；按视觉优先级顺序入场；不得在独立动画元素下方垫完整原图 |
| **概念文案** | 一句话观点转视觉（如"我们严重低估了 X"） | 把主张翻译成**一个**具体视觉隐喻；隐喻不靠角落说明文字也能读懂；最强动作留给被强调的词或反转点 |
| **流程 / 数据** | 步骤、对比、架构、排名、因果链 | 让镜头或焦点跟随变化的值；用真实形状、标签和状态，不只画装饰线；数据映射精确，中间状态可视觉验证 |
| **稿转场景** | 整段口播稿需要连续动效覆盖 | 紧密相关的句子合并为完整视觉单元；每个场景只分配**一个主导视觉命题**；先按旁白估时长，再设计转场 |

## 2. 默认时长与规格假设

| 场景 | 默认时长 |
|---|---|
| 静态标题/参考图入场 | 4s |
| 概念一句话动画 | 4-6s |
| 流程/数据场景 | 5-8s |
| 信息卡/关键结论落定后 hold | ≥1s |
| 主体动作弧 | 尽量给足约 3s，不用高速入场掩盖不可读 |
| settle/hold（每个主动作收尾） | ≥0.5s |

画幅与帧率：默认跟随主项目（16:9 → 1920x1080@30fps；竖屏 9:16 按项目规格）；不把 30fps 的时序假设套给 60fps 项目。终态画面要 hold 到可读完（通常占片尾 18-25%）。

## 3. 时间相位比例（短动效通用节奏）

各相位**交叠推进**，不顺序排满；保持因果关系可读：

| 相位 | 范围 | 作用 |
|---|---:|---|
| Establish（建立） | 0-12% | 交代画布、语境或镜头初始状态 |
| Primary action（主动作） | 8-38% | 绘制、选择、展开、组装或揭示主体结构 |
| Main content（主内容） | 28-68% | 引入标题、主体、数字或核心变化 |
| Secondary detail（次级细节） | 55-82% | 补充标签、图标、高亮或冲击效果 |
| Hold & micro-motion（定格微动） | 78-100% | 回到目标帧并保持可读 |

## 4. 自然语言 → 动作语言翻译表

用户说这些词时，按下表翻译成动作设计（分镜的"剪辑/声音"列和导演简报都要用动作因果描述，不罗列动画预设名）：

| 用户说法 | 翻译成 |
|---|---|
| 有冲击力 | 短促果断的 ease-out、一次可控过冲或冲击帧、强尺度/位置对比 |
| 高级 | 更少同时出现的元素、克制间距、平滑减速、清晰层级 |
| 科技感 | 精确网格、扫描/聚焦行为、克制的辉光、数据感时序；禁止随机霓虹堆砌 |
| 像设计软件搭出来的 | 光标路径、点击/拖拽状态、选框、控制点、蒙版、逐层搭建 |
| 镜头推进 | 有明确目标的景深视差和缩放，不是整页均匀 zoom |
| 扁平 | 形状、蒙版、缩放、位移；不硬加 3D 透视 |
| 微动 | 主动作落定后 2-6px 浮动、1-3° 旋转或 2-5% 缩放脉冲 |
| 有趣 / 有梗 / 好玩 | 一个清晰反差 + 一个记忆点动作 + 一个干净收尾；不加花活 |
| 更生动 / 更有戏 | 让主体完成一次状态改变，再带性格恢复 |
| 轻松 / 俏皮 | 更快的预备动作、更软的落点、一次俏皮的小反转或回弹 |

## 5. 趣味性策略

- 先找**反差**再找动作：笨重变轻巧、安静变爆发、混乱变整齐；
- 每条动效至少一个**记忆点**：一个动作梗、一次状态反转、或一个收尾回扣；
- 有趣优先靠**动作逻辑和节奏**，不靠更多粒子、更多发光、更多标签；草稿平淡时先升级动作逻辑，再考虑加装饰；
- 同一画面能同时"说明"和"有戏"时，保留戏剧性，让说明退到次级层级。

## 6. 覆盖模式（A-roll / B-roll 同屏关系）

分镜中标注动效/素材条目时，同步声明该时间段的覆盖模式，装配阶段（`video-polish`）按此执行：

| 模式 | 含义 | 典型用法 |
|---|---|---|
| A-only | 只有人物主画面 | 观点、情绪、可信度段落 |
| B-only | 只有素材/动效全屏 | 流程解释、证据展示、概念隐喻 |
| AB-live | 人物与 B-roll 同屏，再选布局：`B-base-A-PiP`（B 底 + 人物小窗）/ `A-base-B-overlay`（A 底 + 半幅 B 叠加）/ `B-base-A-cutout`（B 底 + 人物抠像）/ `AB-split`（分屏） | 长解释段需要人物连续性时 |

规则：

- 相邻 B-roll 合并视为一个**连续覆盖段**（coverage run），段内布局稳定，只在语义/布局边界改变；
- 不制造小于 2s 的无意义 A-only 回切碎片；人物回切必须可读、有叙事理由；
- 布局以新片段进入时必须与剪点同帧对齐（不出现半秒旧布局残留）；
- 全屏解释超过约 8s 时优先考虑 AB-live 保持人物连续性；
- **人物降级角标**：素材/证据密集的段落里人物常驻时，优先圆形头像章（chip）或抠像贴角，锚定在画面下 1/3 带的左下/右下角，不飘在中高位，不占满画幅。

## 6a. 排版预算与进场纪律（防堆积）

一条 B-roll/动效镜头内部的构图与节奏预算：

- **一个节拍只有一个主角**：重音元素说完就降权让位（retire），下一个主体进场；同屏主体组 ≤3（降权留守的元素计入），每镜至少保留一个空象限；
- **新元素只在语义拍边界进场**：不机械执行"一句口播一个新元素"——这是堆积型凌乱的制度根源；解说词驱动画面的正确方式是每句都有**活的画面响应**（相机微动/idle/既有元素的状态变化），而不是每句都塞新东西；
- **三段式铁律**：入场 0.2-0.8s → hold（必须带 idle 微动，不许完全静止）→ 出场 0.15-0.5s；入场永远比出场用力；同屏重音同一时刻只能有一个；
- **切镜后 ≤10 帧内必须有主视觉入场**；人物在场时先定人脸安全区，任何文字/卡片/字幕及其背景全时段不得侵入；
- 枢轴句（"但这次不是 X"式转折）的动效归它开启的**下一镜**，先清过场舞台。

## 7. 引擎选择速查（规划层）

详细路由见 [motion-engine-decision.md](motion-engine-decision.md)。规划分镜时的速查：

| 需求特征 | 首选 | 理由 |
|---|---|---|
| 嵌套数据、可变长列表、条件布局、跨视频复用的组件族 | **Remotion** | React/TS 组件化、props 类型化 |
| 固定流程卡、标题卡、对比卡、真实媒体合成、快速一次性场景 | **HyperFrames** | HTML 直接预览、迭代快、自带 lint/validate |
| 真实证据、人物、产品、地点 | 真实素材/录屏 | 不用动效伪造证据 |

不要让同一条目在两个引擎里都做（除非声明过的 A/B 试验）。

## 8. 导演简报输出结构

分镜表中每条 Remotion / HyperFrames / B-roll 动画设计条目，必须附带以下结构的简报（`video-plan` 写入 `remotion_candidate_list.md` / 动效候选；`b-roll-generate` 写入 `brief.md`）：

```text
画面理解：<一句话说明这条动画真正表达什么>
核心视觉：<主元素、视觉顺序和最终定格>
推荐动作：<动作之间的因果关系，不罗列动画预设>
趣味钩子：<最有记忆点的一秒，或最有反差的一步；无则写"无">
时间轴：<时间 / 动作 / 镜头焦点 三列表格，标注帧数>
图层拆分：<必须独立重建或控制的元素清单>
微动与音效：<支持主题的细节；音效标可选或必需，默认 N/A>
负面约束：<不能出现的风格偏差、内容错误和技术伪影>
制作判断：<2D / 2.5D / 3D，及理由；默认 2D>
覆盖模式：<A-only / B-only / AB-live(+布局)>
```

规划输出结尾声明：

```text
当前不执行制作。确认后按此导演简报进入实现。
```

## 9. 风格预览闸门（三帧一样片）

进入批量实现前，用最低成本确认风格，避免整批返工：

1. 每条动效（或同风格第一批）先出 **3 张关键帧静图**：入场帧、动作峰值帧、终态帧；
2. 同风格条目出 **1 条 3s 短样片**（代表性节奏 + 转场）；
3. 用户确认风格后才批量生成其余条目；调整意见只影响未实现条目，已确认条目不静默重做。

静图与样片保存到该条目工作区 `qa/` 下，作为后续实现的对照基准。

## 10. 执行验收清单（交付前逐项核对）

- 首帧、中点帧、终帧非空白且语义连贯；终帧匹配已确认的简报/参考；
- 文字精确、可读、在容器和安全区内；主元素使用批准的颜色和层级；
- 镜头运动服务于主体，不像幻灯片翻页；微动不改变布局、不遮挡相邻元素；
- 只有一个主要动效；开始状态、动作峰值、静态终态、hold 全部存在；
- **真图硬规**：话题存在可截的真实页面（产品官网/GitHub/文档）时，浏览器/页面类镜头用真实截图，禁止代码 mock 冒充；mock 只用于无真实对应物的示意 UI 且简报注明原因；
- **标注坐标机器实测**：真实截图上的环/框/箭头/高亮坐标用 DOM 边界或逐像素量测定，禁止目测；会滚动/移动的素材上，标注钉在内容坐标系随内容动，不钉屏幕固定位；
- 所有运动确定、帧驱动（`useCurrentFrame`/GSAP timeline），无 `Math.random()`/`Date.now()`/CSS 不确定动画；两次渲染同一 QA 帧一致；
- 遵守本合集单镜头纪律与 QA 规则（见 `skills/b-roll-generate/SKILL.md` Gate 4）。
