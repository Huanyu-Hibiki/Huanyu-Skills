# Skill Optimization Protocol

本协议把 SkillOpt 的“轨迹驱动、有界文本更新、验证闸门、最佳产物”思想适配到视频制作管线。目标是从真实协作中学习，同时防止一次性意见、错误归因和自我修改污染生产 Skills。

## 证据层级

| 等级 | 例子 | 默认动作 |
|---|---|---|
| 强 | 用户明确纠正；实际文件/命令证明错误；高风险边界被突破 | 立即记录，可单次提案 |
| 中 | 同类返工、超时、重复询问、阶段交接缺字段 | 记录；累计 2 次后提案 |
| 弱 | Agent 自评、审美猜测、一次性顺利经验 | 不单独提案，等待其他证据 |

信号类型限定为：`user_correction`、`task_failure`、`rework`、`missing_guardrail`、`successful_pattern`、`tool_friction`、`handoff_gap`、`scope_error`。

## 优化单元

1. 优先修改一个目标文件和一个行为命题。
2. Skill 负责决策规则；脚本负责重复且可确定的动作；模板负责稳定输出结构；shared reference 负责跨阶段契约。
3. 项目专属事实留在项目，不进入通用 Skill。
4. 修改预算默认 120 个增删行；超预算拆成多个候选。

## 数据分离

- 训练证据：用于发现问题和产生候选。
- 留出案例：未被当前候选引用，用于比较基线与候选。
- 回归案例：过去已解决的高风险行为，长期保留并重复验证。
- 拒绝缓冲：保留未提升或产生回退的候选及原因。

## Gate 判定

候选必须满足：

```text
candidate_passes > baseline_passes
AND regressions == 0
AND all critical cases pass
AND structural checks pass
AND changed_lines <= budget
```

相等不采纳。无法客观判断时标记失败或补充案例，不用主观描述替代验证。

## 采纳与回滚

Gate 通过只代表“可供采纳”，不代表自动上线。采纳需要用户明确确认；采纳时核对基线哈希，保存目标备份并原子替换。发现线上回退时，以备份恢复，并把回退作为新的强证据写入账本。

## 隐私与保留

证据只保存最小必要摘要，不保存完整对话、模型思维、工具参数和工具输出。脚本做基础秘密模式脱敏，但不能替代人工检查。`.skillopt-video/` 默认本地保存并被 Git 忽略；用户可定期删除旧证据。
